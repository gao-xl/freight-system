# 开发标准总览

> 本手册是**全体二开人员必须遵循的统一标准**。它把散落在各设计文档里的规范，整理成一套覆盖「开发流程 → 编码规范 → 扩展点位 → 工程规范 → 高可用运维 → 架构演进」的完整指引。**所有后续开发都以此为准。**

## 这是一套标准，不是零散笔记

标准意味着三层要求：

1. **必须遵守**：涉及权限、数据隔离、金额、迁移、安全的部分是硬性红线，违规会导致安全或数据事故。
2. **有章可循**：每个扩展点都有「标准做法」和「可照抄的例子」，不需要每次从零摸索。
3. **自动可查**：判断你的需求走哪条路，先看下面的决策表。

## 决策表：你的需求走哪条路

| 你的需求 | 走哪条路 | 需要写代码吗 |
|----------|-----------|:---:|
| 业务表单（订单/客户）多记几个字段 | [自定义字段](/dev/custom-fields) | 否 |
| 业务异常自动预警 / 校验拦截 | [业务规则](/dev/business-rules) | 否 |
| 调整状态流转规则 | [流程配置](/dev/workflow) | 否 |
| 定制单证/提单版式 | [打印模板](/dev/print-template) | 否 |
| 公司特色统计报表 | [报表](/dev/reports) | 否 |
| 订单创建后推送 / 联动你的系统 | [事件订阅](/dev/events) | 少量 |
| 对接一家新的外部服务商 | [外部对接适配器](/dev/adapters) | 一个文件 |
| 做一个全新业务模块/页面 | [新增业务模块](/dev/crud-module) 或 [插件](/dev/plugins) | 是 |

> 判断原则：**能在 Web UI 配置的（字段/规则/流程/模板/报表）一律不写代码**；需要代码时，优先走事件、适配器、插件，**不修改核心文件**。

## 如何开始

第一次接触的团队，按这条路径读一遍即可覆盖绝大多数场景：

**核心概念 → 二开哲学 → 快速上手 → 自定义字段 → 业务规则 → 事件订阅 → 插件**

读完后，开发前先看 [纪律与最佳实践](/dev/best-practices)，上线前对照 [高可用与运维](/deploy/docker) 和 [可观测性](/dev/observability) 检查。

::: tip 本标准的定位
它不是一份「仅供参考」的文档，而是**团队开发契约**。任何与本文档冲突的做法，都应先质疑自己的方案，而不是绕过标准。
:::
