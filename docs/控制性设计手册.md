## 1. 异常处理与日志规范

### 1.1 现状
- 已有统一响应 `ok/fail` 与 `asyncHandler`（[response.js](file:///c:/Users/im/Desktop/新建文件夹/freight-system/backend/src/utils/response.js)）。
- `server.js` 已有全局错误处理中间件，但仅 `console.error`，无结构化日志。

### 1.2 三层异常分类
| 类型 | 示例 | 处理 |
|------|------|------|
| 业务异常 | 记录不存在、无权限、状态不允许 | 返回 `fail`，业务错误码 |
| 校验异常 | 入参缺失、格式错误 | 返回 400 + joi 错误码 |
| 系统异常 | 数据库连接失败、未知错误 | 返回 500 + 记录日志，不泄露堆栈 |

### 1.3 全局错误处理中间件（增强 `server.js`）
```js
const { fail } = require('./utils/response');
const logger = require('./utils/logger');

app.use((err, req, res, next) => {
  // 业务异常（带 code 与 httpStatus）
  if (err.isBusiness) return fail(res, err.message, err.code, err.httpStatus || 400);
  // 校验异常
  if (err.name === 'ValidationError') return fail(res, err.message, 40001, 400);
  // 未知异常
  logger.error('Unhandled error', { url: req.originalUrl, message: err.message, stack: err.stack });
  return fail(res, '服务器内部错误', 50000, 500);
});
```

### 1.4 结构化日志（winston）
```js
// src/utils/logger.js
const winston = require('winston');
const logger = winston.createLogger({
  level: process.env.LOG_LEVEL || 'info',
  format: winston.format.combine(
    winston.format.timestamp(),
    winston.format.json()
  ),
  transports: [
    new winston.transports.Console(),
    new winston.transports.File({ filename: 'logs/app.log', maxsize: 10 * 1024 * 1024, maxFiles: 5 }),
  ],
});
module.exports = logger;
```

### 1.5 日志脱敏规范
- 禁止打印：密码、JWT Token、API Key、银行卡号。
- 手机号/邮箱脱敏：`138****0001`。

### 1.6 规范要点
- 业务层抛错统一 `throw new AppError(message, code, httpStatus)`。
- 控制器不 catch，交给全局中间件。
- 关键操作（登录、删除、财务变动）记录操作日志（见 §2）。

## 2. 操作审计设计

### 2.1 目标
记录"**谁，在何时，对什么资源，做了什么操作**"，实现数据可追溯。

### 2.2 数据模型（AuditLog）
```js
const AuditLog = sequelize.define('AuditLog', {
  id: { type: DataTypes.INTEGER, primaryKey: true, autoIncrement: true },
  userId: { type: DataTypes.INTEGER },
  username: { type: DataTypes.STRING(50) },
  module: { type: DataTypes.STRING(30) },      // order / finance / system
  action: { type: DataTypes.STRING(30) },      // create / update / delete / login
  targetId: { type: DataTypes.INTEGER },       // 目标记录 id
  json: { type: DataTypes.TEXT },              // 变更前后快照（可选）
  ip: { type: DataTypes.STRING(45) },
  userAgent: { type: DataTypes.STRING(255) },
}, { timestamps: true });
```

### 2.3 审计中间件
```js
// src/middleware/audit.js
async function audit(module, action) {
  return async (req, res, next) => {
    const oldJson = res.json.bind(res);
    res.json = (body) => {
      AuditLog.create({
        userId: req.user?.id, username: req.user?.username,
        module, action, targetId: req.params.id,
        ip: req.ip, userAgent: req.get('user-agent'),
      }).catch(() => {});
      return oldJson(body);
    };
    next();
  };
}
```

### 2.4 接入方式
```js
// 路由级审计
router.post('/orders', authRequired, requirePermission('order','create'), audit('order','create'), order.create);
```

### 2.5 审计范围
| 模块 | 需审计操作 |
|------|-----------|
| 认证 | 登录成功/失败、改密 |
| 订单/订舱/报关/单证 | 创建、更新、删除 |
| 财务 | 创建、更新、删除、收款 |
| 报价 | 创建、确认、转订单 |
| 系统 | 角色/权限/用户变更 |
| 对接 | 触发同步 |

## 3. 事务与并发控制

### 3.1 事务边界
以下操作必须用 `sequelize.transaction()`，保证原子性：
- 报价单 + 明细批量写入
- 报价转订单（建 Order + 落财务）+ 状态更新
- 订单详情级联更新（订舱/报关/财务）
- 财务收款（金额变更 + 状态变更）

```js
const t = await sequelize.transaction();
try {
  const order = await Order.create(body, { transaction: t });
  await FinanceRecord.bulkCreate(financeList, { transaction: t });
  await t.commit();
  ok(res, order);
} catch (e) {
  await t.rollback();
  throw e;
}
```

### 3.2 并发控制（乐观锁）
- 适用于并发编辑场景（如订单、财务记录）。
- 模型加 `version` 字段，更新时 `WHERE version=?`，影响行数 0 则冲突。

```js
// 模型
version: { type: DataTypes.INTEGER, defaultValue: 0 }

// 更新
const updated = await Model.update(body, {
  where: { id, version: req.body.version },
});
if (!updated[0]) throw new AppError('数据已被他人修改，请刷新后重试', 40910, 409);
```

### 3.3 防重复提交
- 前端：提交按钮 loading + 禁用。
- 后端：关键"创建"操作做幂等（如重复的 `orderNo`/`quoteNo` 唯一键冲突返回友好提示）。

### 3.4 唯一约束
- 业务单号（orderNo/quoteNo/bookingNo/declNo）加唯一索引，防止重复生成。

## 4. API 规范与错误码

### 4.1 通用规范
- 前缀 `/api`，RESTful 风格。
- 统一响应：`{ code, message, data }`（沿用现有 `ok/fail`）。
- 分页：`page/pageSize`，返回 `{ list, total, page, pageSize }`。
- 鉴权：除登录外均需 `Authorization: Bearer <token>`。

### 4.2 HTTP 状态码
| 状态码 | 含义 |
|--------|------|
| 200 | 成功 |
| 400 | 参数错误/校验失败 |
| 401 | 未登录/凭证失效 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 409 | 冲突（并发/重复） |
| 429 | 请求过于频繁（限流） |
| 500 | 服务器内部错误 |

### 4.3 业务错误码表（code 字段）
| 区间 | 含义 |
|------|------|
| 0 | 成功 |
| 1xxx | 通用错误（1=业务失败，1000=参数缺失） |
| 2xxx | 认证授权（2001=未登录，2003=无权限） |
| 3xxx | 订单/订舱 |
| 4xxx | 财务 |
| 5xxx | 报价 |
| 6xxx | 对接/集成 |
| 7xxx | 数据/校验 |
| 50000 | 未知系统错误 |

> 业务错误码具体清单在实现时随模块补充，本文档定义编码规则。

### 4.4 命名规范
- 路由：小写复数名词。
- 资源操作：`GET /orders`、`POST /orders`、`PUT /orders/:id`、`DELETE /orders/:id`。
- 动作类：`POST /quotations/:id/convert-order`。

## 5. 定时任务设计

### 5.1 场景
| 任务 | 频率 | 说明 |
|------|------|------|
| 船期/ETD/ETA 预警 | 每日 | 临近到期订单推送提醒 |
| 超期应收预警 | 每日 | 应收账款超账期提醒 |
| 报表日结 | 每日 | 生成日报/日结数据 |
| 对接同步 | 按需/定时 | 港口/海关/财务数据拉取 |

### 5.2 技术选型
- 轻量：**node-cron**（单实例，适合单服务器）。
- 后续多实例：改用 Redis 分布式锁或独立调度服务。

```js
// 示例：每日 09:00 超期应收预警（node-cron）
const cron = require('node-cron');
cron.schedule('0 9 * * *', async () => {
  const overdue = await FinanceRecord.findAll({
    where: { status: 'unpaid', dueDate: { [Op.lt]: new Date() } },
  });
  // 推送提醒逻辑
});
```

### 5.3 任务管理
- 任务注册在 `src/jobs/` 目录，统一 `startJobs()` 启动。
- 任务执行记录日志，失败告警。
- 定时任务需要权限/审计（如数据导出）。

## 6. 数据与质量管控

### 6.1 数据字典
- 统一维护枚举/字典：运输模式、费用类型、状态等。
- 后端常量文件 + 前端字典 store 共用，避免硬编码散落。

```js
// src/constants/dict.js
module.exports = {
  ORDER_STATUS: { draft: '草稿', confirmed: '已确认', in_progress: '进行中', completed: '已完成', cancelled: '已取消' },
  MODE: { sea: '海运', air: '空运', land: '陆运', rail: '铁路' },
  // ...
};
```

### 6.2 数据导入导出
| 能力 | 方案 |
|------|------|
| Excel 导入（客户/订单） | `xlsx` 解析 + 校验 + 批量入库（事务） |
| 报表导出 | `exceljs` 生成 Excel / PDF |
| 导出权限 | 需 `read` 权限，导出大文件走异步任务 |

### 6.3 备份与恢复
- 数据库：启用云 RDS 每日备份 + WAL 归档（PITR）。
- 恢复演练：定期执行恢复演练，验证备份可用。
- 文件备份：单证文件目录纳入备份。

### 6.4 监控与告警
| 指标 | 告警阈值 |
|------|----------|
| 服务健康 | 探活失败 N 次 |
| 接口错误率 | > 5% |
| 数据库慢查询 | > 1s |
| 磁盘使用率 | > 80% |
| 连接池 | 接近上限 |

### 6.5 测试方案（质量）
| 层级 | 工具 | 覆盖 |
|------|------|------|
| 单元测试 | Jest | service 层、金额计算 |
| 接口测试 | Supertest | API 契约、错误码 |
| 回归 | 手测 + 脚本 | 核心流程（订单/报价/财务） |
