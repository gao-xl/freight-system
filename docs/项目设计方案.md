## 1. 项目概述

### 1.1 背景
国内中小货代普遍存在：订单靠 Excel/邮件、多岗位信息不同步、财务对账繁琐、客户查询靠人工。本项目提供一个**轻量、可私有化部署、上手快**的货代运营管理系统。

### 1.2 产品定位
- **用户**：国内中小货代公司（10~100 人）
- **形态**：Web 管理后台（B/S 架构），可单服务器私有化部署
- **核心价值**：订单全流程在线化、多岗位协同、财务结算一体化、客户自助跟踪

### 1.3 角色与权限
| 角色 | 职责 | 权限侧重 |
|------|------|----------|
| admin | 系统管理 | 全部 + 用户/配置管理 |
| manager | 业务经理 | 全部业务 + 审批 |
| operator | 操作员 | 订单、订舱、报关、单证、跟踪 |
| finance | 财务 | 财务模块 + 业务只读 |
| viewer | 只读 | 全部只读 |

权限体系为 **RBAC + 数据范围（Data Scope）**：

- **功能权限（RBAC）**：`用户 → 角色 → 权限点`，细到"模块×操作"（详见《权限控制设计.md》）。
- **组织归属（部门组）**：用户可归属一个或多个**业务组**（青岛组/上海组/财务组…），单据打上归属组与归属人。
- **数据范围（Data Scope）**：角色配置 `all / group / self` 三档，限制"看全部 / 本组 / 本人"数据，隔离跨组越权。

## 4. 系统架构

```
                         ┌─────────────────────────────────┐
                         │           客户端浏览器            │
                         │   Vue3 管理后台 + 客户查询门户     │
                         └───────────────┬─────────────────┘
                                         │ HTTPS / JSON-REST
                         ┌───────────────▼─────────────────┐
                         │          Nginx (反向代理/SSL)      │
                         └───────────────┬─────────────────┘
                                         │
                         ┌───────────────▼─────────────────┐
                         │    Node.js 应用服务 (无状态, 多实例) │
                         │  Express + Sequelize + JWT 中间件  │
                         └──────┬──────────────┬────────────┘
                                │              │
              ┌─────────────────▼───┐   ┌──────▼───────────────┐
              │  PostgreSQL 主库     │   │  外部对接适配层        │
              │  (连接池/备份/主从)   │   │  港口/海关/财务 EDI    │
              └─────────────────────┘   └───────────────────────┘
```

**架构要点**
- **前后端分离**：Vue3 SPA + REST API。
- **应用无状态**：JWT 鉴权，可水平扩容。
- **分层清晰**：`routes → controllers → services → models`（当前为 routes→controllers→models，可补 services 层）。
- **适配器模式**：外部系统统一 `send()/query()` 接口。

## 5. 数据库设计

### 5.1 数据库选型
- **PostgreSQL 14+**，替代现有 SQLite。
- 表结构由 Sequelize 模型管理，开发用 `sync`，**生产用 Migration**。

### 5.2 数据表（11 张核心表）

| 表 | 说明 | 关键字段 |
|----|------|----------|
| User | 系统用户 | username, role, status |
| Customer | 客户档案 | code, name, level, creditLimit |
| Supplier | 供应商 | code, name, category, paymentTerms |
| Order | 业务订单 | orderNo, customerId, type, mode, serviceType, status, ETD/ETA |
| Booking | 订舱单 | bookingNo, orderId, supplierId, vesselName, status |
| CustomsDeclaration | 报关单 | declNo, orderId, hsCode, status |
| Document | 单证 | docType, docNo, orderId, status |
| ShipmentTrack | 运输跟踪 | orderId, stage, location, eventTime |
| FinanceRecord | 财务流水 | orderId, direction, category, amount, currency, status |
| IntegrationConfig | 外部对接配置 | code, baseUrl, apiKey, authType, enabled |
| **Quotation** | **报价单** | **quoteNo, customerId, type, mode, originPort, destPort, currency, status, totalAmount, validUntil** |
| **QuotationItem** | **报价明细（费用项）** | **quotationId, name, category, unit, quantity, unitPrice, currency, amount** |

> 报价模块由 `Quotation`（报价单头）与 `QuotationItem`（报价费用明细）两张表组成，详见《报价模块详细设计.md》。

### 5.3 核心关系

```
Customer 1 ── N Order 1 ── N Booking
                        1 ── N CustomsDeclaration
                        1 ── N Document
                        1 ── N ShipmentTrack
                        1 ── N FinanceRecord
Supplier 1 ── N Booking
```

### 5.4 关键设计点
- **金额**：`DECIMAL(15,2)`，金额与币种分离存储（`amount` + `currency`）。
- **状态机**：订单 `draft→confirmed→in_progress→completed/cancelled`。
- **软删除**（可选）：财务、订单等关键数据建议加 `deletedAt`。
- **审计字段**：`createdAt/updatedAt` 由 Sequelize 自动维护。

## 6. 后端 API 设计

### 6.1 REST 风格
- 统一前缀 `/api`
- 统一响应格式：`{ code, message, data }`
- 鉴权：除登录外均需 `Authorization: Bearer <token>`

### 6.2 API 清单

| 模块 | 主要接口 |
|------|----------|
| 认证 | POST /auth/login, GET /auth/me, POST /auth/change-password |
| 看板 | GET /dashboard, /dashboard/order-status, /dashboard/mode-dist, /dashboard/recent-orders |
| 客户 | GET/POST/PUT/DELETE /customers, GET /customers/:id, /customers/stats |
| 供应商 | GET/POST/PUT/DELETE /suppliers |
| 订单 | GET /orders, GET /orders/:id/detail, POST/PUT/DELETE /orders/:id |
| 订舱 | GET/POST/PUT/DELETE /bookings |
| 报关 | GET/POST/PUT/DELETE /customs |
| 单证 | GET/POST/PUT/DELETE /documents |
| 跟踪 | GET/POST/PUT/DELETE /tracks |
| 财务 | GET /finance, /finance/summary, /finance/monthly-trend, POST/PUT/DELETE |
| 对接 | GET/POST/PUT/DELETE /integrations, POST /integrations/trigger |
| 报价 | GET /quotations, GET /quotations/:id, POST /quotations, PUT /quotations/:id, DELETE /quotations/:id, POST /quotations/:id/convert-order |

### 6.3 建议新增/增强
- **补 services 层**：抽出业务逻辑，控制器只做编排。
- **分页标准化**：统一 `page/pageSize` 与 `total` 返回。
- **入参校验**：增加统一校验中间件。
- **报价模块**：新增 `Quotation` 模型与接口（MVP 刚需，当前缺失）。

## 8. 外部系统对接

|--------|----------|------|

| 海关系统 | 单一窗口/电子口岸 | 报关申报、放行状态（详见《报关与EDI对接方案.md》） |
| 财务系统 | 金蝶/用友/ERP | 应收应付凭证、开票、对账 |
| 美元支付 | 美元快付 / 荣e通 | 美元在线支付、电子发票、对账（详见《美元支付平台对接方案.md》） |

## 9. 部署与运维

### 9.1 部署拓扑
- **应用服务**：Docker 容器，部署在云服务器，可多实例 + Nginx 负载均衡。
- **数据库**：云 RDS PostgreSQL 托管实例（推荐），独立于应用。

### 9.2 环境变量（`.env`）
```ini
PORT=3000
JWT_SECRET=<高强度随机串>
DB_HOST=<rds地址>
DB_PORT=5432
DB_NAME=freight
DB_USER=freight
DB_PASSWORD=<强密码>
DB_POOL_MAX=10
DB_SSL=false
```

### 9.3 高可用与备份
- 云 RDS 开启主备高可用 + 每日自动备份 + WAL 归档（PITR）。
- 应用无状态，多实例水平扩容。

### 9.4 CI/CD（可选）
- GitHub Actions / 云效：构建镜像 → 推送仓库 → 部署到服务器。

## 10. 安全设计

| 层面 | 措施 |
|------|------|
| 认证 | JWT（12h 过期），密码 bcrypt 加密 |
| 授权 | 角色权限控制（middleware `requireRole`），后端强制校验 |
| 传输 | Nginx 强制 HTTPS |
| 输入校验 | 统一入参校验，防注入 |
| 数据库 | 最小权限专用账号、SSL 连接、云安全组白名单 |
| 密钥 | JWT_SECRET 走环境变量，不入代码库 |
| 审计 | 关键操作记录操作日志（可选） |

## 11. 迭代路线

- [ ] 搭建 Vue3 + Vite + Element Plus 前端工程
- [ ] **报价/询价模块**（新增后端接口 + 前端页面，详见《报价模块详细设计.md》）
- [ ] **权限控制（RBAC）**（详见《权限控制设计.md》）
- [ ] **安全加固**（详见《安全设计.md》）
- [ ] **个性化基础**：自定义列表列、角色化工作台、**待办任务中心**（各角色每天第一屏聚合"今天该做的单"，覆盖销售/操作/单证/财务）

- [ ] **流程状态可视化**：订单详情展示流转图（当前节点/历史轨迹）
- [ ] 各模块前端页面开发
- [ ] 登录/权限/路由守卫落地
- [ ] 功能回归测试与部署上线

### 阶段二：增强
- 运输跟踪 + 客户自助查询门户（客户企业级角色授权）

- **青岛港针对性功能**：出口7节点看板、放行/装载舱单监控、码头分流、本地费用（详见《青岛港针对性功能设计.md》）

- **单证状态机 + 自动生成套打**：提单/装箱单/发票从订单数据派生，套打模板（详见《打印模板设计功能方案.md》）
- **单票成本/毛利核算**：按票归集应收应付，核算单票毛利（财务+管理层共同刚需）

- **数据权限（Data Scope）**：RBAC 之上叠加"全部/本部门/本人"数据范围（组织归属 + 数据范围设计详见《权限控制设计.md》第 11 节）

### 阶段三：规模化
- 多币种汇率、EDI 数据交换、多租户
- **汇率/气象API接入**：多币种换算 + 风浪预警（详见《免费第三方API对接方案.md》）
- **EDI 落地**：EDIFACT 订舱/提单/状态报文，与船司/航司互通（详见《报关与EDI对接方案.md》）
- **审批流引擎**：可配置审批节点（审批意见/时间留痕）
- **自动对账**：应收应付按订单/单号自动匹配核销
- **财务报表自动生成**：应收账龄、回款率、利润表（定时任务）
- **多语言/多时区**：跨国团队支持

## 12. 开源与模块化改造

> 完整方案见《开源与模块化改造方案.md》。本节为归档摘要。

### 12.1 决策
| 项 | 决策 |
|----|------|
| 开源授权 | **双授权**（核心框架 MIT + 增值模块商业授权） |
| 模块粒度 | **核心框架 + 业务插件** |
| 仓库形态 | **Monorepo + npm workspaces** |
| 开源范围 | **全量开源**（代码公开，许可矩阵分级） |

### 12.2 目标架构
```
freight-system/
├── apps/            # 组装入口（api 后端 / web 前端）
├── packages/core    # 核心框架（auth/RBAC/打印引擎/对接层/定时任务/模块注册）
├── packages/ui、router、api   # 前端共享
└── packages/modules # 业务插件（customer/order/booking/customs/finance/port...）
```

### 12.3 模块化机制
- **后端**：模块导出 `{ models, routes, services, seed, menu }`，由 `ModuleRegistry` 自动加载并收集模型、挂载路由、登记菜单。
- **前端**：`RouteRegistry/MenuRegistry` 动态注册路由与菜单，按权限过滤（复用现有 `MainLayout`）。

### 12.4 二次开发扩展空间
为**货代公司定制**预留系统化扩展点（核心可升级、定制可插拔、配置优先于代码），六大扩展点：
- **自定义字段**：订单/客户加字段不改代码，动态表单渲染。
- **流程状态机配置**：订单状态可配置流转，而非写死 ENUM。
- **业务规则引擎**：毛利预警、超限拦截等可配置。
- **事件/钩子机制**：核心事件可被公司插件订阅，对接公司 OA/企微/邮件。
- **报表自定义**：公司特色统计/对账，通用报表执行。
- **模块插件化**：公司定制写成独立插件。

> 详见《二次开发扩展空间设计.md》。此语义层与本节 Monorepo 结构在批次 C 合并，形成"核心框架 + 配置化定制 + 公司插件"完整二开体系。

### 12.5 双授权许可矩阵
| 层级 | 内容 | 授权 |
|------|------|------|
| 核心框架 | auth/RBAC、订单主数据、打印引擎、对接层、定时任务 | MIT |
| 基础模块 | 订单、订舱、单证基础 | MIT |
| 增值模块 | 报关、财务、港口/青岛港、EDI、客户门户 | 商业授权/LGPL |

### 12.6 实施阶段
1. **Monorepo 骨架**：npm workspaces + git init + LICENSE + .gitignore + .env.example。
2. **核心框架抽取**：db/config/utils/middleware 入 core，实现 ModuleRegistry。
3. **业务模块切片**：现有 controllers/models/routes 迁入各 module-*。
4. **开源完善**：README/CONTRIBUTING/CI/测试。
5. **增值模块授权**：双授权声明 + NOTICE。

> 详见《开源与模块化改造方案.md》。
