# 二开指南（扩展点手册）

> 面向想基于本系统做二次开发的团队（个人货代 / 3-4 人小团队）。

## 1. 新增业务模块

系统所有列表页都基于**通用 CRUD 工厂** `backend/src/controllers/baseController.js` 的 `crudController()`，一个标准模块只需 3 个文件：

**① 模型 `backend/src/models/Xxx.js`**

```js
const { DataTypes } = require('sequelize');
module.exports = (sequelize) => sequelize.define('Xxx', {
  code: { type: DataTypes.STRING, unique: true },   // 业务编号加唯一约束
  name: { type: DataTypes.STRING, allowNull: false },
  amount: { type: DataTypes.DECIMAL(14, 2) },        // 金额一律 DECIMAL，禁止 FLOAT
  status: { type: DataTypes.STRING, defaultValue: 'active' },
  groupId: { type: DataTypes.INTEGER },              // 数据隔离字段（可选）
  ownerId: { type: DataTypes.INTEGER },
});
```

并在 `models/index.js` 里注册 + 声明关联（`belongsTo/hasMany`）。

**② 控制器 `backend/src/controllers/xxxController.js`**

```js
const { crudController } = require('./baseController');
const { Xxx } = require('../models');

module.exports = crudController({
  model: Xxx,
  searchFields: ['code', 'name'],        // 关键字模糊搜索字段
  order: [['id', 'DESC']],
  protectedFields: ['groupId'],          // 禁止前端篡改的字段
  scoped: true,                          // 开启数据隔离（模型需有 groupId/ownerId）
});
```

工厂自带：分页列表 / 详情 / 创建 / 更新 / 删除 / 批量删除 / 批量更新 / 数据隔离。

**③ 路由 `backend/src/routes/index.js`**

```js
const xxx = require('../controllers/xxxController');
router.get('/xxx', guard('xxx', 'list'), xxx.list);
router.post('/xxx', guard('xxx', 'create'), xxx.create);
// ... get/update/delete 同理
```

**前端**：在 `frontend/src/views/` 加页面，`router/index.js` 注册路由并配 `meta.permission`，菜单会自动按权限显隐（`MainLayout.vue` 的 `hasPermission` 过滤）。

## 2. 新增对接适配器

所有外部系统（船期/汇率/港口/报关/AIS/场站…）都是 `backend/src/integrations/adapters/` 下的一个文件，**统一接口签名**：

```js
// backend/src/integrations/adapters/myCarrier.js
const axios = require('axios');

const code = 'my_carrier';   // 与 IntegrationConfig 表中的 code 对应

async function query(cfg, payload) {
  // cfg：运行期从 IntegrationConfig 表读取（baseUrl/apiKey 等，无需改代码配置）
  const resp = await axios.get(cfg.baseUrl, {
    params: { key: cfg.apiKey, ...payload },
    timeout: 8000,
  });
  return resp.data;
}

async function send(cfg, payload) {
  // 只读类适配器直接抛错即可
  throw new Error('该适配器只支持查询');
}

module.exports = { code, name: '我的船司', send, query };
```

现有 12 个适配器（aisTracking / customs / exchangeRate / finance / freightRate / port / portQingdao / portShanghai / portNingbo / shipSchedule / usdPay / yardQingdao）都可作范本。**对接密钥永远走 `IntegrationConfig` 表或环境变量，禁止写死进代码。**

## 3. 新增预警规则

规则引擎在 `backend/src/services/alertService.js`，**每条规则 = 一个函数**，每 30 分钟自动扫描 + 启动即跑：

```js
// 示例：箱超期未还预警
async function ruleContainerOverdue() {
  const rows = await Container.findAll({ where: { /* 超期条件 */ } });
  for (const c of rows) {
    await upsertAlert({
      type: 'container_overdue',
      level: 'warning',
      orderId: c.orderId,
      title: `箱号 ${c.containerNo} 超期未还`,
      message: `应还箱日期 ${c.returnDueAt} 已过`,
      dueAt: c.returnDueAt,
      dedupKey: `container_overdue:${c.id}`,   // 幂等键：同一件事只报一次
    });
  }
}
```

然后在 `runAllRules()` 里加一行 `await ruleContainerOverdue();`。

**纪律**：必须用 `upsertAlert` + `dedupKey`（防重复轰炸）；单条规则报错不影响其他规则。

## 4. 新增自动化动作

自动化引擎在 `backend/src/services/automationService.js`——规则不止"报警"，还能"自己动手"（推进节点/生成财务）。**每个动作 = 一个幂等函数**：

```js
async function autoMyAction() {
  const rows = await Something.findAll({ where: { /* 触发条件 */ } });
  let acted = 0;
  for (const r of rows) {
    if (/* 目标状态已满足 */) continue;     // 幂等：先判断再执行
    await r.update({ /* 执行动作 */ });
    await logAudit('auto_my_action', r.id, `自动完成 XXX`);  // 必留痕，操作员 SYSTEM
    acted++;
  }
  return acted;
}
```

然后在 `runAutomations()` 汇总返回里加上它。随定时任务每 30 分钟执行，也可手动 `POST /api/automation/run` 触发。

**纪律**：先判断目标状态再执行（幂等）；每个动作写 `AuditLog`；单动作失败 `try/catch` 隔离。

## 5. 新增单证类型与打印模板

**单证类型**：改 `backend/src/controllers/documentController.js` 两处常量即可：

```js
const DOC_META = {
  // ...
  booking_note: { title: '托书', prefix: 'BN' },   // 新增一行
};
const DOC_FLOW = { draft: ['issued', 'archived'], /* 状态机流转白名单 */ };
```

之后 `GET /documents/generate?orderId=&docType=booking_note` 即可一键生成。

**打印模板**：不用改代码——在系统里维护 `PrintTemplate`（按 docType + isDefault），`printService` 会用 `resolveFields` 把订单/客户/箱货数据填进模板渲染 HTML 套打。

## 6. 数据隔离与权限

- **RBAC**：Role / Permission / UserRole / RolePermission 四表；接口用 `guard('模块','动作')` 保护，前端菜单按 `hasPermission` 自动显隐。
- **数据隔离**：模型带 `groupId/ownerId` 即可在 `crudController` 里开 `scoped: true`，列表/详情/写操作自动按范围过滤。个人/小团队单机用可不开（默认管理员全量可见）。
- **审计**：所有写操作走 `audit` 中间件自动落 `AuditLog`；自动化动作用 `SYSTEM` 身份留痕。

## 8. 订阅事件（事件驱动扩展）

系统内置事件总线 `src/services/eventBus.js`：所有 `crudController` 管理的写操作会自动发射 `created/updated/deleted` 事件；领域动作（如订舱装船、报关完成）由对应控制器手动发射。二开者无需改核心代码，订阅事件即可挂自己的逻辑（如"订单创建后推送到企业微信 / webhook"）。

```js
// 任意服务或启动文件里
const events = require('../services/eventBus');

// onAsync：异常被捕获，不影响主流程
events.onAsync('order.created', async (env) => {
  // env = { event: 'order.created', payload: { id, data, user }, time: '...' }
  console.log('收到新订单', env.payload.data);
});

// 也支持同步 on（需自行 try/catch）
events.on('finance.created', (env) => { /* ... */ });
```

**事件清单**（完整定义在 `eventBus.js` 的 `EVENT_TYPES`）：

| 模块 | 事件 |
|------|------|
| 订单 | order.created / order.updated / order.deleted / order.transitioned |
| 客户 | customer.created / customer.updated / customer.deleted / customer.followed |
| 订舱 | booking.created / booking.updated / booking.deleted / booking.shipped |
| 报关 | customs.created / customs.updated / customs.deleted |
| 单证 | document.created / document.updated / document.deleted / document.generated |
| 财务 | finance.created / finance.updated / finance.deleted / finance.billed |
| 报价 | quotation.created / quotation.updated / quotation.deleted / quotation.confirmed / quotation.converted |
| 跟踪 | track.created / track.updated / track.deleted |
| 系统 | alert.created / alert.resolved / automation.executed / user.login |

> 在 `src/server.js` 启动阶段注册监听最稳妥：进程生命周期内只注册一次。现有的预警/自动化引擎已通过此机制实现"事件即时触发"。

## 9. 加自定义字段（零代码定制）

覆盖 80% 的"我们公司还想记一个 XX 字段"诉求，无需改表、无需改前端表单——通过配置即可。

1. 定义字段（管理员）：

```bash
curl -X POST http://localhost:3000/api/custom-fields \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"biz":"order","name":"poNo","label":"客户PO号","fieldType":"text","isList":true,"isSearch":true}'
```

字段属性：

| 字段 | 说明 |
|------|------|
| biz | 业务对象：order / customer / booking / finance / quotation 等 |
| fieldType | text / number / select / date / boolean |
| options | fieldType=select 时的可选项数组 |
| isList | true 时该字段出现在列表页（前端按此动态渲染列） |
| isSearch | true 时该字段可被搜索（仅标 isList 的字段参与检索，避免全表 JSON 扫描） |

2. 读写业务记录上的自定义字段值（业务模型已带 `customFields` JSON 列）：

```bash
# 读
GET /api/order/custom-fields?refId=123
# 写（覆盖式）
PUT /api/order/custom-fields
{ "refId": 123, "values": { "poNo": "PO-2026-001" } }
```

> 前端按 `GET /api/custom-fields?biz=order` 拉取字段定义，动态渲染表单与列表列；搜索时把 `isSearch` 字段拼进查询参数即可。SQLite 下 JSON 列检索走应用层过滤，量大建议切 PostgreSQL（JSONB 索引）。

## 10. 写插件（ModuleRegistry 协议）

插件化二开入口。一个插件 = 一个目录 `backend/src/modules/<name>/index.js`，按协议导出，由 `ModuleRegistry` 统一加载。

```js
// backend/src/modules/invoice/index.js
const { guard } = require('../../middleware/permissionService');
const invoiceCtrl = require('../../controllers/invoiceController');
const Invoice = require('../../models/Invoice');

module.exports = {
  name: 'invoice',                 // 必填，唯一标识，与目录名一致
  title: '发票管理',                // 中文名（日志/菜单）
  dependencies: ['order'],          // 前置模块，决定加载顺序
  models: [Invoice],                // 本模块 Sequelize 模型
  routes(router, mw) {              // 路由声明函数 (router, mw) => void
    router.get('/invoices', guard('invoice', 'read'), invoiceCtrl.list);
  },
  services: { invoiceService },     // 对外暴露的服务
  seed: async () => { /* 初始化数据 */ },
  menu: { path: '/invoices', icon: 'Tickets', permission: 'invoice:read' },
  events: ['invoice.created'],      // 本模块发射的事件
  // autoMount 省略（默认 true）：路由由 ModuleRegistry 自动挂载
};
```

**加载机制**（`src/core/moduleRegistry.js`）：

- `ModuleRegistry.load(dir)` 扫描 `backend/src/modules/` 下的**子目录** `index.js`，只登记元信息、**不碰 Express 路由表**；
- 显式调用 `mountRoutes(router, mw)` 才挂载路由（`autoMount: false` 的模块会被跳过，用于路由已在别处注册的存量模块）；
- 加载与挂载分离，往 `modules/` 丢一个新目录不会静默改变现有路由。

**现存样板**：`src/modules/customer/index.js`——客户是存量功能，路由已在 `src/routes/index.js` 注册，故设 `autoMount: false` 避免重复挂载。新模块直接定义 `routes` 即可默认挂载。

> 插件协议的最佳文档是可运行的例子：先看 `customer` 样板，再照抄改写。Phase 3 会在此基础上做 Monorepo 物理拆分，模块边界已被验证、拆分风险低。
