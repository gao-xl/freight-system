# 数据访问层收敛方案（controllers → dataAccess → models）

> 版本：v1.0　日期：2026-08-09　状态：已落地
> 关联文档：`docs/架构解耦重构方案-高内聚低耦合.md`（目标分层架构 §2、依赖方向规则 §4.3）
> 落地提交：`d1009e8`（refactor(architecture): 收敛控制器对模型的直接访问）
> 代码证据：文件均位于 `backend/`，改动以 `文件:行号` 标注

---

## 0. 执行摘要

本次改动收敛了存量「controller 直连 model」的两层扁平结构在控制器层的入口，目标是让架构方案中的依赖方向铁律从纸面落到 lint 规则。改动包含三件事：

- 新增 `src/services/dataAccess.js` 数据访问服务层，作为控制器唯一允许的模型访问出口。
- 将 35 个控制器、43 处 `require('../models')` 统一改为 `require('../services/dataAccess')`，并修正 `onboardingController.js` 绕过入口的 `require('../models/UserRole')`。
- 在 `.eslintrc.js` 新增铁律 4：`import/no-restricted-paths` 禁止 `src/controllers` 从 `src/models` 取模型，依赖方向固化为 `controllers → services → models`。

动机是架构方案中「无仓储层」的高耦合热点（第 1.4 节热点 6）：控制器直接调度模型，数据访问分散、换表结构波及面广。本次先建立访问边界，不引入完整仓储层，符合方案「MVP 阶段不为每个模型建 repo，只为被多域引用的模型建访问门面」的务实原则。

---

## 1. 背景：为什么收敛

### 1.1 现状问题

架构方案第 1.4 节将「无仓储层」列为耦合热点 6：全 `controllers/services` 直调 Model，数据访问分散。在控制器层具体表现为：

- 35 个控制器文件顶部 `const { X } = require('../models')` 直取模型，控制器把「取数据」和「拼响应」混在一起。
- 部分控制器还以**内联形式**在方法体内临时 `require('../models').Xxx`（如 `financeController.js:161,214`、`orderController.js:194,242,256`、`documentController.js:154`），形态更隐蔽，难统一治理。
- 有 1 处绕过聚合索引、直接引用模型单文件路径：`onboardingController.js:15` `require('../models/UserRole')`。

### 1.2 既有契约与空白

架构方案的依赖方向规则（§4.3）已明确「禁止 controllers 直接查 models」，当时的 `.eslintrc.js` 也已有铁律 1–3（禁依赖控制器层、FinanceRecord/AuditLog 跨域写收口）。但铁律 1–3 的 `no-restricted-imports` 只能按字面 import 路径匹配，模型经 `models/index.js` 聚合导出时字面路径不含模型名，规则无法命中；且 `overrides` 对 `src/controllers/**` 整体放行了架构限制。因此「控制器直连模型」这一横切面始终游离在规则之外。本次为它补上铁律 4。

## 2. 目标设计

### 2.1 数据访问服务层

新增 `backend/src/services/dataAccess.js`：

```js
const models = require('../models');

module.exports = {
  ...models,
  sequelize: models.sequelize,
};
```

它转出 `models/index.js` 的全部导出（模型 + sequelize 句柄），被放置于 `services/` 而非 `models/`，使依赖方向落在服务层：`controllers → services/dataAccess → models`。控制器由此获得稳定的、被规则许可的模型访问入口，同时保留 `models/index.js` 作为唯一关联定义权威源，不复制模型定义。

### 2.2 依赖方向铁律

在 `.eslintrc.js` 的 `import/no-restricted-paths` 追加一条 zone：

```js
// 铁律 4（E8）：全量收敛——controllers 层不得直接从 models 层取模型
{ target: './src/controllers', from: './src/models' },
```

语义：`src/controllers` 目录下的文件禁止 import `src/models` 目录下的任何路径。同时收紧 overrides，让 `src/controllers/**` 不再豁免该规则——仅保留 `no-restricted-imports` 放行，以允许控制器依赖同层 `baseController` 与子层 `services/domains/utils/middleware`。

设计取舍：

- 用 `import/no-restricted-paths` 按**目录**匹配，弥补 `no-restricted-imports` 按字面路径匹配不到聚合导出模型的盲区。
- 治理范围限定在控制器层，`services/`、`domains/`、`core/` 仍可直接访问模型（它们本就是数据访问的合法来源），避免一次性扩大改动面。
- 铁律 2/3（FinanceRecord/AuditLog 跨域写收口）不因本层豁免：`dataAccess.js` 仍导出这两个模型，但其**写操作**的约束由 `domains/finance` 与 `core/auditService` 承担，与本次改动互补。

## 3. 改动明细

### 3.1 新增文件

- `backend/src/services/dataAccess.js`：数据访问服务层入口，转出 `models/index.js` 全部导出。

### 3.2 控制器收敛（35 文件 / 43 处）

| 形态 | 说明 | 涉及 |
|------|------|------|
| 顶层解构 | `const { X } = require('../models')` → `require('../services/dataAccess')` | 31 个控制器，各 1 处 |
| 内联 require | 方法体内 `require('../models').Xxx.method(...)` → 同一替换 | `financeController.js:161,214`、`orderController.js:194,242,256`、`documentController.js:154` |
| 内联 sequelize | `const { sequelize } = require('../models')` → 同一替换 | `financeController.js:7`、`roleController.js:62` |
| 绕过入口修正 | `onboardingController.js:15` `require('../models/UserRole')` → 并入顶层解构 `const { User, Role, UserRole } = require('../services/dataAccess')` | 1 处 |

### 3.3 配置变更

- `backend/.eslintrc.js`：新增铁律 4 zone；收紧 overrides 使 `src/controllers/**` 保留 `import/no-restricted-paths` 约束。

### 3.4 未改动项

- `require('../controllers/baseController')`、`require('./baseController')` 等同层/子层引用保持原样。
- `services/`、`domains/`、`core/`、`middleware/` 对模型的直接访问未动（它们本就是合法数据访问来源）。
- 模型定义与关联（`models/index.js`）未动。

## 5. 影响与后续

- 本次改动是纯路径收敛，无业务逻辑变化，接口行为不变，风险低。
- 依赖方向现固化为 `controllers → services/dataAccess → models`，后续新增控制器须从 `dataAccess` 取模型，否则 lint 直接报错。
- 已具备的配套约束仍生效：`services/` 与 `domains/` 的模型访问不受影响；跨域写 FinanceRecord/AuditLog 仍须走对应域门面。
- 后续可继续：按架构方案第 1.4 节热点 6，为被多域引用的模型建立真正带查询语义的访问门面（如 `orderService.getOrdersBy(…)`），以及推进 P1 清理路由双轨 / 薄壳模块 / 转发层。
