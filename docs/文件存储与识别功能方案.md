# 文件存储与识别功能方案

> 版本：v1.0
> 定位：在现有单证上传基础上，建成**通用文件存储 + 内容识别**能力，支持全文搜索、自动识别单证类型、结构化关键字段抽取。
> 范围：Word(.docx/.doc)、PDF、Excel(.xlsx/.xls)。不含 OCR 扫描件识别（扫描版图片文字属二期可选）。
> 关联：见《文档总览索引.md》"通用能力"主题；底座为《技术栈缺陷与改造清单.md》与《数据库稳定性改造方案.md》。

---

## 1. 现状与目标

### 1.1 现状
现有 [documentController.js](../../backend/src/controllers/documentController.js) 已支持单证附件上传/下载/预览，存本地 `uploads/`，兼容 word/pdf/excel MIME。但**只存文件，不读内容**——无法按文件内容搜索、无法自动识别类型、无法抽取关键字段回填业务。

### 1.2 目标
- **全文搜索**：按文件内文本（如提单号、箱号、发票号、船名）检索到对应文件。
- **自动识别单证类型**：根据内容/文件名自动判断提单、装箱单、发票、原产地证等。
- **结构化抽字段**：抽取提单号、箱号、船名、金额、日期等回填业务单据。
- **统一文件底座**：不只服务单证，也服务报价、报关、财务等模块的附件。

## 2. 技术选型

| 能力 | 方案 | 说明 |
|------|------|------|
| 文件存储 | 本地磁盘 | 沿用 `uploads/` 目录，私有化部署零成本 |
| docx 解析 | `mammoth` | Word 文档 → 文本/HTML |
| doc 解析 | `textract`（或 `word-extractor`） | 老版 .doc 二进制 |
| xlsx 解析 | `xlsx`（SheetJS） | Excel → 二维数组/文本 |
| pdf 解析 | `pdf-parse` | PDF 文本层抽取（非扫描件） |
| 全文检索 | 数据库全文索引 | SQLite FTS5 / PostgreSQL `tsvector`，文件量级足够 |

> 说明：识别基于**文档文本层**，扫描版 PDF/图片需 OCR（二期可选，可接 Tesseract）。

## 3. 数据模型

### 3.1 File 表（通用文件存储，替代/扩展 Document.filePath）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | — |
| bizType | STRING(30) | 业务类型：document/quotation/customs/finance/order |
| bizId | INTEGER | 业务单据 id |
| category | STRING(30) | 文件分类（可选） |
| fileName | STRING(200) | 落地存储名（uuid+ext） |
| originalName | STRING(200) | 原始文件名 |
| mimeType | STRING(100) | MIME |
| ext | STRING(10) | 扩展名 |
| size | INTEGER | 字节数 |
| filePath | STRING(255) | 相对路径 |
| textContent | TEXT | 提取的全文文本（供搜索） |
| docType | STRING(30) | 识别出的单证类型（bl/packing_list/...） |
| keyFields | JSON | 结构化抽取字段（{blNo, containerNo, vessel...}） |
| status | ENUM | pending/extracting/done/failed |
| uploadBy | INTEGER | 上传人 |

索引：`(bizType, bizId)`；全文检索字段 `textContent`。

### 3.2 与现有 Document 的关系
- 短期：在 Document 上**追加** `textContent / docType / keyFields / status` 字段，复用现有上传/下载/预览。
- 中期：抽公共 File 表作为通用底座，Document 关联或迁入（列入批次 C）。

## 4. 识别管线

```
上传 → 存盘 → 异步解析 → 提取文本 → 类型识别 → 字段抽取 → 回填
        │         │          │
        │         └ 失败重试（队列）          │
        └ 返回 filePath，前台可先预览          └ textContent/docType/keyFields
```

### 4.1 解析器（按扩展名分发）
```
ext .docx → mammoth.extractRawText
ext .doc  → word-extractor
ext .xlsx/.xls → xlsx.read → 遍历 sheet 拼接文本
ext .pdf  → pdf-parse
其他      → 跳过（仅存文件）
```

### 4.2 类型识别规则（关键词 + 正则，按命中得分）
| 类型 | 特征关键词/正则 |
|------|----------------|
| 提单 bl | `BILL OF LADING`、`MBL`/`HBL`、提单号正则 |
| 装箱单 packing_list | `PACKING LIST`、`PACKING LIST/WEIGHT MEMO` |
| 发票 invoice | `INVOICE`、`COMMERCIAL INVOICE` |
| 原产地证 certificate_of_origin | `CERTIFICATE OF ORIGIN`、`C.O.`、`FORM E` |
| 装箱单/舱单其他 | 按配置扩展 |

### 4.3 关键字段抽取（正则/规则）
| 字段 | 说明 |
|------|------|
| blNo 提单号 | `[A-Z]{3}\d{10,}` 等 |
| containerNo 箱号 | `[A-Z]{4}\d{7}` |
| vessel 船名/航次 | 上下文规则 |
| invoiceNo 发票号 | 发票类 |
| amount 金额 | 货币符号 + 数字 |
| date 日期 | 各类日期格式 |

> 规则集中在 `识别规则配置表`（可后台维护），正则可热更新。

## 5. API 设计

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/files/upload` | multipart 上传，返回 filePath |
| GET | `/files` | 列表（按 bizType/bizId 过滤） |
| GET | `/files/search?q=` | 全文搜索（命中 textContent） |
| GET | `/files/:id/download` | 下载原文件 |
| GET | `/files/:id/file` | 在线预览 |
| GET | `/files/:id/extract` | 查看解析结果（textContent/docType/keyFields） |
| POST | `/files/:id/re-extract` | 手动重新解析 |
| DELETE | `/files/:id` | 删除（含磁盘文件） |

权限沿用 `guard('document', ...)` 或新 `file` 资源，纳入 RBAC。

---

## 6. 异步与失败处理

- 解析放入**轻量队列**（先行 node-cron 轮询 `status=pending` 的任务，二期上 BullMQ）。
- 失败：`status=failed` + 错误信息，支持手动重试；不阻塞上传主流程。
- 大文件/长文本：解析限时，超时置 failed。

---

## 7. 落点与批次

| 批次 | 内容 |
|------|------|
| **批次 A（立即）** | Document 追加字段、mammoth/xlsx/pdf-parse 解析器、上传后异步提取文本、类型识别规则、全文搜索接口 |
| **批次 B（上线前）** | 关键字段抽取、识别规则后台配置、前端"文件识别结果"展示面板 |
| **批次 C（二期）** | 抽公共 File 底座、BullMQ 队列、PG 全文检索(tsvector)、(可选)OCR |
