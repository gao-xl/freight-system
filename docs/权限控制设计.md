# 权限控制（RBAC）详细设计

> 版本：v1.0
> 所属项目：《项目设计方案.md》阶段一 MVP
> 目标：将现有"写死的角色枚举"升级为**完整 RBAC（角色-权限）**体系，可后台配置、细粒度到"模块×操作"

---

## 1. 现状与问题

### 1.1 现状
- `User.role` 为写死枚举：`admin / manager / operator / finance / viewer`（[User.js](file:///c:/Users/im/Desktop/新建文件夹/freight-system/backend/src/models/User.js)）
- `requireRole(...roles)` 中间件**已写好但未在路由中使用**（[auth.js](file:///c:/Users/im/Desktop/新建文件夹/freight-system/backend/src/middleware/auth.js)）
- 所有路由仅用 `authRequired`（只校验登录），**无任何角色权限限制**

### 1.2 问题
1. 权限不可配置，改权限需改代码。
2. 粒度粗，无法按"模块+操作"（如"可看订单但不可删订单"）控制。
3. 无法扩展新角色/新权限。
4. 前端菜单、按钮无法按权限动态显隐。

## 2. 目标架构（经典 RBAC）

```
 ┌──────────┐   N:N   ┌──────────┐   N:N   ┌────────────┐
 │  User    │────────▶│  Role    │────────▶│ Permission │
 │ (用户)    │         │ (角色)    │────────▶│ (权限点)     │
 └──────────┘         └──────────┘         └────────────┘
     用户─角色                            角色─权限
```

**三层模型**
- **User（用户）**：一个用户可拥有多个角色。
- **Role（角色）**：一组权限的集合，如"操作员""财务""经理"。
- **Permission（权限点）**：最小授权单元，格式 `模块:操作`，如 `order:create`、`finance:read`。

**权限判定**：`User → 所属角色 → 拥有权限 → 命中某接口所需权限`。

## 3. 数据模型设计

### 3.1 新增 3 张表 + 2 张关联表

#### 3.1.1 Role（角色）
```js
const Role = sequelize.define('Role', {
  id: { type: DataTypes.INTEGER, primaryKey: true, autoIncrement: true },
  code: { type: DataTypes.STRING(30), allowNull: false, unique: true }, // 如 operator
  name: { type: DataTypes.STRING(50), allowNull: false },               // 如 操作员
  description: { type: DataTypes.STRING(255) },
  isSystem: { type: DataTypes.BOOLEAN, defaultValue: false }, // 系统内置角色不可删
}, { timestamps: true });
```

#### 3.1.2 Permission（权限点）
```js
const Permission = sequelize.define('Permission', {
  id: { type: DataTypes.INTEGER, primaryKey: true, autoIncrement: true },
  module: { type: DataTypes.STRING(30), allowNull: false },  // order / finance / quotation ...
  action: { type: DataTypes.STRING(30), allowNull: false },  // create / read / update / delete / approve
  name: { type: DataTypes.STRING(50), allowNull: false },    // 如 "删除订单"
  code: { type: DataTypes.STRING(60), allowNull: false, unique: true }, // order:delete
}, { timestamps: true });
```

#### 3.1.3 UserRole（用户-角色 关联）
```js
const UserRole = sequelize.define('UserRole', {
  id: { type: DataTypes.INTEGER, primaryKey: true, autoIncrement: true },
  userId: { type: DataTypes.INTEGER, allowNull: false },
  roleId: { type: DataTypes.INTEGER, allowNull: false },
}, { timestamps: true });
```

#### 3.1.4 RolePermission（角色-权限 关联）
```js
const RolePermission = sequelize.define('RolePermission', {
  id: { type: DataTypes.INTEGER, primaryKey: true, autoIncrement: true },
  roleId: { type: DataTypes.INTEGER, allowNull: false },
  permissionId: { type: DataTypes.INTEGER, allowNull: false },
}, { timestamps: true });
```

### 3.2 关联关系
```
User.belongsToMany(Role, { through: 'UserRole', as: 'roles' })
Role.belongsToMany(User, { through: 'UserRole', as: 'users' })
Role.belongsToMany(Permission, { through: 'RolePermission', as: 'permissions' })
Permission.belongsToMany(Role, { through: 'RolePermission', as: 'roles' })
```

### 3.3 兼容现有 `User.role`
- 保留 `User.role` 作为**默认主角色**（快速判断），同时通过 `UserRole` 支持**多角色叠加**。
- 迁移时用 `seed` 为每个现有用户创建对应角色并关联。

| finance | 财务读写 + 业务只读 |

## 5. 后端实现要点

### 5.1 中间件改造（`middleware/auth.js`）
新增 `requirePermission` 中间件，替代/补充 `requireRole`：

```js
const { Op } = require('sequelize');
const { sequelize } = require('../models');

// 校验用户是否拥有指定权限（支持 admin 通配）
async function requirePermission(module, action) {
  return async (req, res, next) => {
    if (!req.user) return res.status(401).json({ code: 401, message: '未登录' });
    // admin 拥有全部权限
    if (req.user.role === 'admin') return next();
    // 查询用户角色包含的权限
    const perms = await getPermissions(req.user.id);
    const need = `${module}:${action}`;
    if (perms.includes(need) || perms.includes(`${module}:*`)) return next();
    return res.status(403).json({ code: 403, message: '无权限执行该操作' });
  };
}
```

### 5.2 路由接入（`routes/index.js`）
```js
// 示例：订单模块
router.get('/orders', authRequired, requirePermission('order', 'read'), order.list);
router.post('/orders', authRequired, requirePermission('order', 'create'), order.create);
```

## 6. 前端设计

### 6.1 权限来源
- 登录接口返回 `user.roles` 与 `user.permissions`。
- 前端 store 保存权限集合，用于**菜单显隐 + 按钮显隐 + 路由守卫**。

### 6.2 菜单权限
```js
// 路由 meta 中声明所需权限
{
  path: '/orders',
  meta: { title: '订单管理', permission: 'order:read' }
}
```

### 6.3 按钮权限（指令方式，可选）
```js
// 自定义指令 v-permission="'order:delete'"
app.directive('permission', {
  mounted(el, binding) {
    const perms = useAuthStore().permissions;
    if (!perms.includes(binding.value)) el.parentNode?.removeChild(el);
  }
});
```

### 6.4 路由守卫
```js
router.beforeEach((to) => {
  const auth = useAuthStore();
  if (!auth.token) return '/login';
  if (to.meta.permission && !auth.hasPermission(to.meta.permission)) return '/403';
});
```

### 6.5 权限管理页面
- **角色管理**：角色列表 + 勾选权限树。
- **用户管理**：分配角色给用户。
- **权限点管理**：查看/维护权限点（admin 专属）。

## 9. 迁移与兼容

1. **seed**：初始化 5 个内置角色 + 权限点表 + 默认角色权限。
2. **存量用户**：为每个现有 `User` 按 `user.role` 映射创建 `UserRole` 关联。
3. **平滑过渡**：前期同时保留 `requireRole` 与 `requirePermission`，逐步替换。
4. **内置角色保护**：`isSystem=true` 的角色不可删除，仅可调整权限。

## 11. 部门组（Group）与数据范围（Data Scope）

> 在 RBAC（功能权限）之上，增加**组织归属 + 数据范围隔离**，实现"只能看本部门/本人单据"。

### 11.1 目标
- 用户归属**部门/业务组**（青岛组、上海组、财务组…）。
- 业务单据打上**归属组与归属人**。
- 按配置的**数据范围**过滤可见数据：全部 / 本组 / 本人。

### 11.2 数据模型（新增 2 张表 + 扩展 2 张表）

#### 11.2.1 Group（部门/业务组）
```js
const Group = sequelize.define('Group', {
  id: { type: DataTypes.INTEGER, primaryKey: true, autoIncrement: true },
  code: { type: DataTypes.STRING(30), allowNull: false, unique: true }, // qingdao / shanghai / finance
  name: { type: DataTypes.STRING(50), allowNull: false },               // 青岛组 / 上海组 / 财务组
  parentId: { type: DataTypes.INTEGER },                                // 上级组（可选）
  description: { type: DataTypes.STRING(255) },
}, { timestamps: true });
```

#### 11.2.2 UserGroup（用户-组 关联）
```js
const UserGroup = sequelize.define('UserGroup', {
  id: { type: DataTypes.INTEGER, primaryKey: true, autoIncrement: true },
  userId: { type: DataTypes.INTEGER, allowNull: false },
  groupId: { type: DataTypes.INTEGER, allowNull: false },
}, { timestamps: true });
```

#### 11.2.3 扩展 Role（数据范围）
```js
// Role 增加
dataScope: { type: DataTypes.ENUM('all', 'group', 'self'), defaultValue: 'self' },
// all=全部数据  group=本组数据  self=本人数据
```

#### 11.2.4 业务单据扩展归属字段
以 Order 为例：
```js
// Order 增加
groupId: { type: DataTypes.INTEGER },   // 归属组
ownerId: { type: DataTypes.INTEGER },   // 归属人（操作员）
```
> 报价、报关、财务等需要数据隔离的单据同样追加 `groupId / ownerId`。

### 11.3 关联关系
```
User.belongsToMany(Group, { through: 'UserGroup', as: 'groups' })
Group.belongsToMany(User, { through: 'UserGroup', as: 'users' })
Order.belongsTo(Group) / Order.belongsTo(User, { as: 'owner' })
```

### 11.4 数据范围过滤逻辑（中间件 dataScope）
```js
// 按角色 dataScope 附加过滤条件
// admin / dataScope='all'  → 不加条件
// dataScope='group'        → WHERE groupId IN (用户所属组集合)
// dataScope='self'         → WHERE ownerId = req.user.id
```

### 11.5 兼容与默认
- 默认给所有角色 `self`；`admin` 强制 `all`。
- 存量单据无 `groupId` 时归入"未分组"，仅本人/管理员可见。
- 迁移 seed：为每个用户创建所属组并关联。

### 11.6 前端
- 用户管理页增加"所属组"选择。
- 单据列表按数据范围过滤，组/人被选择器。
- 菜单与列表顶部显示当前数据范围。

### 11.7 验收标准
- [ ] 用户可归属一个或多个组
- [ ] 单据可标记归属组 + 归属人
- [ ] 角色可配置数据范围（all/group/self）
- [ ] admin 始终看全部
- [ ] group 用户只看到本组单据，self 用户只看到本人单据
- [ ] 前端列表按数据范围过滤
