# 业务全流程功能与权限审查

> 版本：v1.0
> 视角：以**核心业务全流程**（订舱 → 报关 → 单证 → 结算 → **放单**）为线索，审查功能断点与权限断点。
> 依据：现有核心模型逐一核对（Order/Booking/CustomsDeclaration/Document/FinanceRecord/ShipmentTrack）。
> 定位：一份**审查报告**，识别断点并提出改造方向；落地细节见《系统功能改进开发任务清单.md》对应任务。

---

## 1. 全流程主链路

```
报价 → 订单 → 订舱 → 报关 → 单证 → 结算(应收/应付) → 放单(正本/电放)
                │       │       │        │              │
                └───────┴───────┴────────┴──────────────┘
                        各环节状态目前互相孤立
```

---

## 2. 功能断点

### 2.1 核心缺失：没有"放单"环节（最严重）
海运业务最关键的**控制点**——**正本/电放（Telex Release）放单**完全缺失：
- 无"放单"状态、无放单记录、无放单方式（正本/电放）。
- 无"先款后放单"的业务控制——货代核心风控（**未结清不放单**）无法在系统内兑现。

### 2.2 各模块状态机孤立，无联动
各模块**各自独立推进**，互不感知，数据靠人工重复录入：

| 模块 | 状态机 | 现状 |
|------|--------|------|
| 订舱 [Booking](../../backend/src/models/Booking.js) | new→confirmed→loading→shipped | 与报关/单证无联动 |
| 报关 [Customs](../../backend/src/models/CustomsDeclaration.js) | prepared→submitted→inspecting→released→rejected→closed | 放行不触发"可装船/可出单" |
| 单证 [Document](../../backend/src/models/Document.js) | draft→issued→sent→received→archived | 无自动生成、无正本/电放类型 |
| 财务 [FinanceRecord](../../backend/src/models/FinanceRecord.js) | unpaid→partial→paid→waived | 结清不触发"可放单" |

**断点示例**：
- "报关已放行"不会自动触发"可装船/可出单"。
- "应收未收齐"不会阻止"放单"。
- 订舱提单号、报关、单证之间无数据继承，需重复录入。

### 2.3 结算环节不完整
- 无对账/开票/核销（任务 B4）。
- 有 `dueDate/paidAmount`，但无账龄分级、无超期拦截。
- 单票成本/毛利缺失（任务 B6）。

### 2.4 单证不完整
- 无自动从订单一键生成（任务 B7）。
- 无正本/电放/顺签/倒签等提单类型；无签发人留痕。

## 3. 权限断点

| 环节 | 现状 | 问题 |
|------|------|------|
| 订舱 | `guard('booking', ...)` | 无"订舱确认"专属权限，操作员可自行确认 |
| **放单** | **无权限点** | 放单是高风险操作，应单设权限 + 审批流 |
| 结算/核销 | `guard('finance', ...)` | 无"核销/豁免"专属权限，财务权限过粗 |
| 单证签发 | `guard('document', ...)` | 无"签发/作废"权限，单证员即可签发 |
| 报关 | `guard('customs', ...)` | 无"放行确认"权限 |
| 数据范围 | 未落地 | 跨组越权（《权限控制设计.md》第 11 节已设计未落地） |

> 现有路由仅用 `guard(module, action)` 粗粒度控制，未细分到"确认/签发/放单/核销"等**高风险动作**。

## 4. 核心改造方向：放单控制 + 状态联动

### 4.1 放单模块（新增）
```
收款未结清 ──▶ 系统拦截放单（正本/电放）
收款结清   ──▶ 允许放单 + 记录放单人/时间/方式
```

- **放单模型** `ReleaseRecord`：orderId、releaseType（正本/电放）、releaseNo、operatorId、releaseAt、approvalStatus、remark。
- **放单控制**：放单前校验应收是否结清；未结清禁止（或走审批）。
- **放单审批**：放单属高风险，可配置审批流（结合《二次开发扩展空间设计.md》流程配置）。

### 4.2 状态联动
- 订舱放行 → 报关放行 → **可装船**。
- 应收结清 → **可放单**。
- 通过统一事件总线（《二次开发扩展空间设计.md》事件钩子）驱动各模块状态联动，取代人工重复录入。

### 4.3 权限细化
- 新增权限点：`order:confirm`、`customs:release`、`document:issue`、`finance:writeoff`、`release:create/approve`。
- 放单、核销、签发、作废等高风险动作**单独授权 + 审批留痕**。

## 6. 验收标准

- [ ] 全流程各环节状态可联动（订舱→报关→装船；应收→放单）
- [ ] 放单前校验应收结清，未结清拦截或走审批
- [ ] 放单记录操作人/时间/方式，可追溯
- [ ] 高风险动作（放单/核销/签发/作废）有独立权限点 + 审批留痕
- [ ] 跨组数据范围隔离生效
