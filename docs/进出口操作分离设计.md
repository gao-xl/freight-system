# 进出口操作分离设计

> 版本：v1.0
> 定位：将现有"进出口混用"的订单/单证/流程，改造为**进口、出口明确的业务分流**，让操作员按进出口维度工作、界面分开、流程独立。
> 决策（已确认）：做到 **① 界面+筛选分离 ② 独立操作流程**（暂不含单证类型拆分 / 操作团队隔离）。
> 关联：见《文档总览索引.md》"业务模块设计"主题；承接《项目设计方案.md》《青岛港针对性功能设计.md》。

---

## 1. 现状与问题

### 1.1 现状
- [Order.js](../../backend/src/models/Order.js) 已有 `type` 字段：`ENUM('import','export','transit')`，默认 `export`。
- 但**仅止于一个字段**：
  - 前端菜单/列表无进出口维度，订单/单证/报关/跟踪全部混在一个列表。
  - 操作流程未区分——出口、进口走同一套节点/状态。
  - 无进出口维度筛选、无独立入口。

### 1.2 问题
1. 操作员无法按"进口/出口"快速定位工作。
2. 出口与进口的业务节点（订舱→装船 vs 舱单→提箱）无差异体现。
3. 看板、预警、统计未按进出口拆分。

---

## 2. 目标架构

```
操作维度（进出口）
 ├── 出口 Export：订舱 → 提箱 → 装箱 → 集港 → 运抵 → 报关 → 放行 → 装船 → 离港
 └── 进口 Import：舱单 → 到港卸船 → 报关放行 → 提箱拆箱 → 空箱归还 → 结算
```

**设计原则**：
- `type` 作为**一级业务维度**贯穿：模型、接口筛选、前端菜单、看板、预警、统计。
- 流程节点**可配置化**（结合《二次开发扩展空间设计.md》流程状态机），进出口各一套默认模板。
- 界面分离：导航分"进口操作 / 出口操作"，列表默认按当前进出口过滤。

## 3. 数据模型改动

### 3.1 Order（现有，增强约束）
```js
// 已有
type: { type: DataTypes.ENUM('import', 'export', 'transit'), defaultValue: 'export' },
// 建议：作为必填且建立索引，供进出口维度筛选
// 新增索引 idx_order_type
```

### 3.2 新增 FlowNode（流程节点，进出口各一套）
```js
const FlowNode = sequelize.define('FlowNode', {
  id:          { type: DataTypes.INTEGER, primaryKey: true, autoIncrement: true },
  bizType:     { type: DataTypes.ENUM('import', 'export'), allowNull: false }, // 进出口
  nodeCode:    { type: DataTypes.STRING(40), allowNull: false }, // booking / pickup / stuffing / ...
  nodeName:    { type: DataTypes.STRING(50), allowNull: false },
  sort:        { type: DataTypes.INTEGER, defaultValue: 0 },
  required:    { type: DataTypes.BOOLEAN, defaultValue: false },
  enabled:     { type: DataTypes.BOOLEAN, defaultValue: true },
}, { timestamps: true });
// 唯一约束 (bizType, nodeCode)
```

### 3.3 新增 OrderNode（订单实例节点，记录进度）
```js
const OrderNode = sequelize.define('OrderNode', {
  id:      { type: DataTypes.INTEGER, primaryKey: true, autoIncrement: true },
  orderId: { type: DataTypes.INTEGER, allowNull: false },
  nodeCode:{ type: DataTypes.STRING(40), allowNull: false },
  status:  { type: DataTypes.ENUM('pending', 'done', 'blocked'), defaultValue: 'pending' },
  doneAt:  { type: DataTypes.DATE },
  remark:  { type: DataTypes.TEXT },
}, { timestamps: true });
```

> 复用《二次开发扩展空间设计.md》的 WorkflowConfig 思路：**进出口流程 = 一组可配置 FlowNode**，公司可改节点顺序/必填/启用。

## 5. 后端改动

### 5.1 筛选接口
- 订单列表支持 `?type=import|export|transit` 过滤。
- 单证/报关/跟踪/财务等关联列表同样按 `type` 过滤（通过关联订单的 type）。

### 5.2 流程接口
| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/orders/:id/nodes` | 订单实例节点进度（按 order.type 返回对应模板） |
| PUT | `/orders/:id/nodes/:nodeCode` | 标记节点完成/卡点 |
| GET | `/flow-nodes?bizType=export` | 流程模板查询（进出口配置） |
| PUT | `/flow-nodes/:id` | 配置节点（启用/必填/排序） |

### 5.3 看板/预警/统计
- 看板按 `type` 分进出口维度。
- 预警按进出口分别触发（出口：订舱/放行/装船；进口：到港/提箱/空箱）。

## 6. 前端改动

### 6.1 菜单/入口分离
- 导航新增 **"出口操作" / "进口操作"** 两个一级入口（或订单/单证列表顶部 Tab 切换）。
- 落点：前端 [router/index.js](../../frontend/src/router/index.js) 与 [MainLayout.vue](../../frontend/src/layouts/MainLayout.vue) 的菜单数组。

### 6.2 列表筛选
- 订单列表默认带 `type` 筛选，进出口切换即刷新。
- 单证/报关/跟踪列表透传 `type`。

### 6.3 流程展示
- 订单详情以**时间线**展示对应进出口节点（绿 done / 黄 pending / 红 blocked），复用青岛港看板样式。
