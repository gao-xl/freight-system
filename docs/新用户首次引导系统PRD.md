# 新用户首次使用引导系统（Onboarding）PRD

- 版本：v1.0（评审稿）
- 日期：2026-08-08
- 状态：待评审
- 归属阶段：Phase 3.8（v2.1 增量）——OPC 开箱体验的最后一公里

---

## 0. 一句话摘要

为首次登录系统的 OPC / 小团队用户，提供一套**可跳过、进度自动派生、按真实数据推进**的三层引导体系，把"从登录到完成第一笔订单"的时间从"数天摸索"压缩到"一顿饭的功夫"，同时保持"高级用户零打扰"。

---

## 1. 问题定义（Problem Statement）

### 1.1 用户遇到的问题

freight-system 目前有 35 个业务模型、20+ 个一级菜单（客户、供应商、订单、订舱、报关、单证、财务、运价、预警、自动化、规则引擎、报表……）。一个从未用过本系统的货代老板，第一次登录后的真实处境是：

- **不知道先配什么**：公司信息要不要填？币种在哪设？权限要不要建？——系统没有任何提示，一切靠猜；
- **空系统没有"反馈"**：客户列表、报价列表、订单列表全是空表格，用户不知道"这算正常吗？下一步做什么？"；
- **核心链路不连续**：建了客户 → 不知道要录报价 → 录了报价 → 不知道转订单 → 下了单 → 不知道财务在哪对账。每一步之间是断的；
- **"试一试"成本高**：空系统里无法体验真实业务流，用户不敢把真实数据录进去，于是停留在"看过没用过"。

### 1.2 成本评估

| 维度 | 影响 |
|------|------|
| 用户侧 | OPC 老板时间极贵，摸索成本 = 放弃成本。货代 SaaS 行业 7 天激活率是留存的第一道闸门 |
| 商业侧 | 本项目核心竞争力是"开箱即用"——如果开箱不"用起来"，二开能力再强也无人问津；对下载者（开源用户）来说，第一印象决定是否继续投入 |
| 商业缺口 | 面向小团队的"开箱即用"引导体验是市场空档；**这正是 OPC 的切入点**——我们不必追求功能全覆盖，但在"3 分钟跑通"体验上必须做到极致 |

### 1.3 数据现状（无埋点，先立假设）

> ⚠️ 诚实声明：当前系统无埋点、无用户行为数据。下述假设需在 v1 上线后通过埋点验证（见 §8）。本项目用户研究以访谈/观察为主，v1 设计依据来自：OPC 定位决策（2026-08-07 已确认）、现有 UI 结构、以及货代行业通用操作习惯。

## 2. 目标（Goals）

### 2.1 用户目标
- 新用户能在 **10 分钟内**完成核心初始化（公司信息 + 默认币种 + 首个客户）；
- 新用户能在 **一个工作日内**走通"客户 → 报价 → 订单 → 订舱 → 财务"完整链路的第一单；
- 新用户始终知道"下一步该做什么"，且**随时可以甩开引导自己干**。

### 2.2 业务目标（可衡量）
| # | 目标 | 衡量方式 | 基线→目标 |
|---|------|---------|-----------|
| G1 | 激活率：完成核心 4 步 Checklist 的新用户占比 | 埋点 | 上线 30 天后 ≥ 60% |
| G2 | 首单时间：注册→首笔订单产生 | 埋点（订单 createdAt - 账号 createdAt） | 中位数 ≤ 3 天（v1 上线前无基线，先立假设） |
| G3 | 打扰度：引导被"跳过/关闭"的比例 | 埋点 | ≤ 30%（说明引导不烦人、恰好够用） |
| G4 | 支持工单：引导相关咨询占比 | 客服记录 | 上线 60 天后占比 < 10% |

## 3. 非目标（Non-Goals）

| # | 不做 | 原因 |
|---|------|------|
| N1 | **强制门禁**：未完成引导就不让用系统 | OPC 用户要的是"边用边学"，拦路 = 赶人。引导永远可跳过 |
| N2 | **教程弹层铺满每个页面**（tooltip 巡游） | 打扰度与引导价值成反比；只做核心链路的空状态引导 |
| N3 | **内置视频教程 / 在线客服** | 那是内容运营的活，不是产品功能；本系统定位开源工具，不自建服务体系 |
| N4 | **用户画像驱动的个性化引导**（A/B 分群、行为触发营销式 onboarding） | 对 3-4 人团队过度设计，且需要埋点基建，超出本次范围 |
| N5 | **为引导单独建状态表 / 独立进度存储** | 进度必须**派生自真实业务数据**（与"订单状态是派生的"哲学一致），避免双写不一致、避免生产库冗余 |
| N6 | **注册流程改造**（手机号验证、邮箱激活等） | 本系统是自部署/开源，无注册环节；引导从"首次登录"开始，不向上游扩展 |

## 4. 设计总览：三层引导体系

> 核心思路：**轻推（Wizard）→ 常驻（Checklist）→ 就地（Empty State + 上下文提醒）**，三层的打扰度递增、覆盖范围递减。

```
┌─ 第一层：首次登录欢迎 Wizard（一次性，可跳过）
│   收集 4 项关键初始化：公司信息 → 默认币种 → 是否批量导入 → 演示数据(可选)
│   ↓ 完成后自动进入 Dashboard
│
├─ 第二层：Dashboard 引导 Checklist（常驻，直到全部完成）
│   核心 4 步 + 进阶 N 步，进度自动派生自真实数据
│   ▸ ① 完善公司信息   ▸ ② 添加首个客户   ▸ ③ 录入第一份报价   ▸ ④ 创建第一笔订单
│   完成核心 4 步 → Checklist 收起为"已完成"横幅，可一键展开回顾
│   ↓ 用户开始正常使用
│
└─ 第三层：就地引导（贯穿使用期）
    ├─ 空状态引导：核心页面（客户/报价/订单/订舱/财务）空数据时显示"下一步建议 + 快捷入口"
    ├─ 上下文提醒：完成 A 后轻提示"下一步：录报价"（Toast，可关）
    └─ 帮助入口：全局右下角"？"浮标 → 打开《二开指南》/ 核心操作手册
```

### 4.1 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| D1 进度如何存储 | **不存储，实时派生**。前端通过现有统计接口 + 轻量探测接口计算完成度 | 与项目"状态派生"哲学一致；零迁移、零双写、生产升级无风险 |
| D2 引导是否强制 | **永不强制**，每层都有"跳过/关闭/不再显示" | OPC 要快，尊重用户自主性 |
| D3 完成后是否消失 | Checklist 核心 4 步完成后**自动收起**为可展开横幅 | 常驻会形成噪音；完成后即退场，符合"打扰度递减" |
| D4 演示数据 | 放 P1，提供"一键生成 + 一键清空" | 对试用者价值大，但污染生产数据风险高；默认不开启 |
| D5 与二开的关系 | 引导组件本身**不阻断二开**；Checklist 步骤可通过事件总线/自定义字段扩展 | 本项目核心是"二开能力"，引导体系不能是封闭的黑盒 |

## 5. 用户故事（User Stories）

按优先级排序：

0. **作为一位刚部署完系统的 OPC 用户**，我希望 `docker compose up` 后系统自动完成建库、迁移、创建默认账号，以便我不记任何命令就能登录，也不用担心把库清掉。
1. **作为一位 OPC 货代老板**，我希望首次登录时系统主动问我"公司叫什么、用什么币种"，以便我不需要翻设置菜单找半天。
2. **作为一位 OPC 货代老板**，我希望登录后首页能明确告诉我"还差哪几步就能跑起来"，以便我知道该做什么而不是对着空表格发呆。
3. **作为一位 OPC 货代老板**，我希望每一步引导都能直接跳到对应页面，以便我不需要在 20 个菜单里找入口。
4. **作为一位只想先看看系统的试用者**，我希望一键生成演示数据、用完一键清空，以便在零风险下体验完整业务流。
5. **作为一位赶时间的老用户**，我希望所有引导都可以一键关闭并且不再出现，以便我的工作流不被打扰。
6. **作为一位 4 人小团队的负责人**，我希望引导能提示我建小组、分配权限，以便团队成员一进来就有合适的视图（而非全员管理员）。
7. **作为一位二开开发者**，我希望引导步骤可扩展（事件可订阅、步骤可增删），以便我给客户交付时能定制自己的初始化流程。
8. **作为一位第二次打开系统的用户**（引导中途退出），我希望进度被记住、下次从断点继续，以便不用重头再来。
9. **作为一位只看不动手的用户**，我希望空状态页面告诉我"这页是干嘛的 + 下一步怎么做"，以便降低学习曲线。

## 6. 需求规格（Requirements）

### 6.1 P0（必做，v1 发布门槛）

#### F1 首次登录欢迎 Wizard
- **触发**：账号首次登录且未完成过 Wizard（判定：前端 localStorage 标记 + 后端 `system:company` 未配置过）。
- **流程**：5 步（含前置改密，仅 `mustChangePassword` 账号出现），全部可"跳过"：
  0. 设置管理员密码（bootstrap 默认账号出现；改密成功 → tokenVersion 递增，旧 token 失效）
  1. 欢迎页（一句话介绍系统价值 + "开始配置"/"直接进入"）
  2. 公司信息（复用 CompanySetting 字段：公司全称/简称/信用代码，**仅必填公司全称**）
  3. 默认币种（单选：USD/CNY/EUR + 汇率，默认 USD；读写 ExchangeRate 表，bootstrap 已预置 USD 基准）
  4. 数据准备（三选一：稍后自己录 / 去批量导入（跳 `/import`）/ 生成演示数据（P1 时出现））
- **完成动作**：写入 CompanySetting + 默认币种 → 跳转 `/dashboard`。
- **验收标准**：
  - [ ] 首次登录的用户看到 Wizard，二次登录不再出现（除非主动重置）
  - [ ] 每一步都有"跳过"，跳过即进入下一步；最后一步"跳过"即直接进入系统
  - [ ] 公司全称为空时"下一步"不可点（唯一强校验）
  - [ ] 填写的公司信息在"系统管理 → 公司设置"中可见
  - [ ] 设置默认币种后，新建订单/报价的币种默认值生效
  - [ ] 断网/刷新时已填步骤不丢失（步骤内本地暂存）
- **技术要点**：`OnboardingWizard.vue` 组件；路由 `/onboarding`（首次登录由 `router` 守卫重定向）；公司信息直接复用现有 `PUT /api/system/company` 接口；默认币种若后端无现成接口，新增轻量 `PUT /api/system/defaults`（后续可并入 SystemSetting）。

#### F2 Dashboard 引导 Checklist（核心）
- **位置**：`/dashboard` 顶部，位于统计卡片上方，卡片式。
- **步骤定义**（核心 4 步 + 进阶 2 步）：
  | # | 步骤 | 完成判定（真实数据派生） |
  |---|------|------------------------|
  | ① | 完善公司信息 | `companyName` 非空（探测 `GET /api/system/company`） |
  | ② | 添加首个客户 | `customerTotal ≥ 1`（现有 dashboard stats 接口） |
  | ③ | 录入第一份报价 | `quotationTotal ≥ 1`（stats 接口扩展或轻量探测） |
  | ④ | 创建第一笔订单 | `orderTotal ≥ 1`（现有 stats 接口） |
  | ⑤（进阶） | 走通订舱/报关 | `bookingTotal ≥ 1` 且 `customsTotal ≥ 1` |
  | ⑥（进阶） | 建第一份对账单 | `GET /api/finance/statement` 有数据 |
- **交互**：
  - 每步右侧"去完成"按钮 → 跳转对应路由（`/system/company`、`/customers`、`/quotations/edit`、`/orders`、`/bookings`、`/finance/statement`）
  - 已完成步骤打勾 + 灰化；完成度进度条（x/6）
  - **核心 4 步全部完成** → Checklist 自动收起为一行横幅"🎉 开箱配置完成，开始接单吧！"（可展开回顾）
  - 卡片右上角"不再显示"（永久关闭，localStorage 标记）
- **验收标准**：
  - [ ] Checklist 显示的依据是真实数据：删掉最后一个客户 → ② 自动回到未完成态
  - [ ] 核心 4 步完成后卡片自动收起为横幅；横幅可展开查看历史步骤
  - [ ] "不再显示"后不再出现（刷新、重登均不出现）
  - [ ] 每步的"去完成"按钮跳转到正确路由
  - [ ] 无权限的角色（如 customer 门户账号）不显示该卡片
- **技术要点**：`OnboardingChecklist.vue`；数据源优先复用 `GET /api/dashboard/stats`（已验证存在 scopedWhere），缺报价/订舱计数时在 stats 接口追加字段（向后兼容）；前端 `onboardingStore.js`（Pinia）负责聚合 + localStorage 标记；**不建后端表**。

#### F3 核心页面空状态引导
- **范围**：客户列表、报价列表、订单列表、订舱列表、财务列表（5 个核心页面）。
- **行为**：列表为空时，表格区域显示空状态插画/图标 + 两行文案：
  - 第一行：这页是干嘛的（一句话）
  - 第二行：下一步建议 + 主按钮（如客户页："添加第一个客户"按钮；订单页空 → "先去录一份报价"引导）
- **特殊逻辑**：订单页空状态额外提示"若已录报价，可一键转订单"；财务页空状态提示"订单出账后自动生成应收，先去创建订单"。
- **验收标准**：
  - [ ] 5 个核心页面在数据为空时显示引导文案，有数据后自动消失（复用现有 `:data="list.length"` 判定，无需新状态）
  - [ ] 每个空状态都有主行动按钮，点击后进入正确的新增/引导流程
  - [ ] 空状态不遮挡页面的筛选/工具栏
- **技术要点**：抽取 `EmptyGuide.vue` 公共组件（props: icon/title/hint/action），5 个页面接入；不改业务逻辑。

#### F4 上下文提醒（Toast 级）
- **场景**：用户完成"上一步"动作后 2-3 秒内，右下角轻提示下一步建议：
  - 创建客户成功 → "已添加客户，下一步：录入一份报价"
  - 保存报价成功 → "报价已保存，下一步：转成订单"
  - 订单创建成功 → "订单已创建，下一步：发起订舱"
- **规则**：每个场景每个账号最多提示 1 次（localStorage 去重）；可一键"不再提示"；手动 dismiss。
- **验收标准**：
  - [ ] 触发时机正确（对应动作成功后）
  - [ ] 同一场景不重复打扰（第 2 次做同样动作不再提示）
  - [ ] Toast 有关闭按钮，5 秒自动消失
- **技术要点**：复用前端现有 eventBus / 或直接在列表页成功回调里触发；**后端 eventBus 不参与**（这是前端 UX 层，避免污染业务事件流）。

### 6.2 P1（应做，快速跟进）

#### F5 演示数据（一键生成 + 一键清空）
- 系统设置内提供"生成演示数据"按钮（写入 3 客户 / 3 报价 / 2 订单 / 1 订舱 / 1 报关 / 若干财务流水，数据带"演示"前缀标记）。
- 提供"清空演示数据"：仅删除带演示标记的记录（事务内完成），不影响用户真实数据。
- 入口：`/system` 系统管理内 + Wizard 第 4 步可选。
- 验收：生成后核心链路可完整查看；清空后不留残余；重复生成幂等（先清后建）。

#### F6 小团队模式（角色引导）
- 检测到"非 admin 用户登录"或"管理员主动选择团队模式"时，Checklist 增加第 ⑦ 步"创建小组并分配权限"（跳 `/system/groups`）。
- Wizard 第 2 步可选"我是团队/我是个人"。
- 验收：团队模式下提示建组；个人模式下不出现该步骤。

#### F7 二开扩展点
- Checklist 步骤定义抽成配置（前端 `onboardingSteps.js` 常量数组，每步含 `{ id, label, check(), action }`），二开者可新增步骤或改写判定。
- Wizard 步骤支持通过事件总线订阅（如"初始化完成"事件）——与现有 eventBus 一致。
- 文档：《二开指南》新增 recipe"如何定制初始化引导"。
- 验收：改 `onboardingSteps.js` 后无需动组件代码即生效；事件订阅示例可运行。

### 6.3 P2（暂不做，留好扩展位）

- 行为埋点面板（激活率/首单时间的可视化报表）——v1 先埋点收集，报表 UI 后续；
- 分角色差异化引导（销售/操作/财务各自的首屏引导）；
- 引导进度跨设备同步（当前自部署单机场景无必要，留 localStorage 结构可迁移）；
- 视频/图文教程库（内容运营范畴，不在产品代码内）。

## 7. 技术方案要点

### 7.1 架构兼容性
| 现有能力 | 本功能的利用方式 |
|---------|-----------------|
| `GET /api/dashboard/stats`（scopedWhere + admin 豁免） | Checklist 完成度主数据源，追加 quotation/booking 计数字段（向后兼容） |
| 路由守卫 `router.beforeEach`（已有 roleHome 逻辑） | 新增：首次登录且未跳过 → 重定向 `/onboarding` |
| Pinia（auth store 已存在） | 新增 `onboardingStore`：聚合完成度 + localStorage 标记（跳过/关闭/提醒去重） |
| 前端构建（npm run build） | 无新增依赖；组件均为 Vue3 + Element Plus |
| 后端 | **零迁移、零新表**（D1 决策）；仅可能新增 `PUT /api/system/defaults`（默认币种）一个轻量接口 |
| 二开体系（eventBus / 自定义字段 / moduleRegistry） | F7 引导步骤配置化 + 事件扩展，保持开放 |

### 7.2 边界与风险
| 风险 | 对策 |
|------|------|
| 引导进度派生依赖 stats 接口 → 接口字段变更破坏判定 | Checklist 判定函数集中在一个模块，接口字段变化只改一处；探测失败时默认"未完成"不报错 |
| localStorage 标记丢失（清缓存）→ 引导重来 | 可接受（重来一次成本低）；进阶方案（P2）存后端 Profile |
| 演示数据污染真实库 | 演示记录统一 `name` 前缀 + 标记字段；清空用事务；生产环境默认隐藏入口 |
| Wizard 强校验引起反感 | 唯一强校验仅"公司全称"；其余全部可跳过 |

### 7.3 基础设施初始化（数据库地基）⭐ 随 v2.1 前置交付

> 引导系统成立的前提是"系统先活着"。现状三个坑：① `server.js` 启动仅 `sync()` 建表，**不建账号/权限点/角色** → Docker 空卷 `up` 后登录页直接报"用户名或密码错误"，开箱即用破功；② 唯一初始化途径 `seed.js` 是 `force:true` 清库重建，让新用户手跑它等于教人开挖掘机除草；③ 默认账号 admin/123456 无强制改密机制，安全底线靠口头承诺。

**目标：任何部署方式（docker / npm start）首次启动零命令即"能登录"，且永不误清数据。**

#### 7.3.1 初始化路径分层（三种场景，互不干扰）

| 场景 | 路径 | 说明 |
|------|------|------|
| 全新空库（Docker / npm start） | **启动自检自动完成**：自动迁移 → 幂等 Bootstrap | 用户零操作，`up` 完即可登录 |
| 已有老库升级 | 仅跑未执行迁移（`AUTO_MIGRATE` 默认开） | 不触碰已有数据，增量补列 |
| 需要演示数据 | `node src/init-db.js --demo`（幂等） | 替代 seed.js；演示记录带 `isDemo` 标记 |

#### 7.3.2 幂等 Bootstrap（server.js 启动自检，`ensureBootstrap()`）

仅当对应表为空时执行，天然幂等、可反复启动、绝不碰已有数据：

1. **Users 表为空** → 创建默认账号 `admin`（初始密码策略见 7.3.3），并给该账号置 `mustChangePassword=true`；
2. **Permissions 表为空** → 插入全量权限点（按 `code` 检查，来源与 seed.js / migration 0012 同源，抽为共享常量文件）；
3. **ExchangeRate 表无 USD 基准** → 预置 USD/CNY 基准汇率（引导 Wizard 的默认币种直接读写此表，无需新接口）；
4. **CompanyProfile 为空** → 不预填，留给 Wizard 第 ① 步（公司信息）。

启动日志输出：`[BOOTSTRAP] 已创建默认管理员 admin（初始密码见文档，首次登录须改密）`。

#### 7.3.3 默认账号与强制改密（安全底线机制化）

- Bootstrap 建出的 `admin` 初始密码 **123456**，同时置 `mustChangePassword=true`；
- User 表新增列 `mustChangePassword`（migration，默认 false）；登录后前端检测该标记 → 强制跳转"设置新密码"页，**改密前路由守卫拦在系统外**；
- 改密成功 → 标记清除 + `tokenVersion` 递增（复用现有 JWT 吊销机制，旧 token 立即失效）；
- 支持 `ADMIN_INIT_PASSWORD` 环境变量预设初始密码（docker compose 可配），设置后 `mustChangePassword=false`（管理员自控场景跳过强制改密）；
- **与引导衔接**：强制改密即 Wizard 的"第 0 步"，天然成为引导第一站（见 F1）。
- **⭐ 引导设计修订建议（2026-08-08）**：行业主流实践已转向"**首个访问用户即管理员、向导内创建账号**"，无预设密码 → 天然无弱口令窗口期，且省去改密心智负担。建议将主路径调整为"**首次访问向导创建首个管理员**"（Wizard 第 0 步由"强制改密"改为"创建管理员账号"）；`ADMIN_INIT_PASSWORD` 环境变量保留为无人值守部署备选（该路径仍带强制改密）。是否采纳待拍板。

#### 7.3.4 自动迁移开关

- 默认启动时执行 umzug 未运行迁移（对 OPC 零命令友好）；`AUTO_MIGRATE=false` 关闭（严谨的大客户/超大生产库自控，锁表风险自担）；
- 前提：迁移文件必须幂等——现有 17 个迁移已按"空库全量验证"标准修复过（`CURRENT_TIMESTAMP`、重复时间戳编号 0010 等），启动自动迁移前补一轮"已有数据 + 增量迁移"验证。

#### 7.3.5 seed.js 处置

- 保留但**降级**：README/文档不再引导新用户使用；新增 `init-db.js`（幂等，`--demo` 生成演示数据、`--force` 才允许清库）；
- 演示数据统一带 `isDemo` 标记 → 引导系统 F5"一键清空演示数据"复用同一字段（事务内按标记删除）；
- 迁移链验证继续用空库（PostgreSQL 测试库跑 `db:migrate` 全量 + bootstrap 验证），不受影响。
