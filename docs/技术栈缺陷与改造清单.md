## 2. 缺陷与风险清单

### 2.1 高优先级（影响正确性/安全，优先处理）

| # | 缺陷 | 风险 | 改造建议 |
|---|------|------|----------|
| H1 | ~~依赖残留 `sqlite3`~~ ✅ 已完成 | ~~死代码、拖慢安装、含原生编译~~ | ~~迁移 PG 完成后删除该依赖~~ 已移除 `sqlite3` 依赖，`config`/`db` 方言固定 postgres，系统 PostgreSQL-only |
| H2 | 无数据库迁移工具（缺 sequelize-cli） | 表结构变更靠手改，生产升级易错 | 引入 sequelize-cli，建立 migrations 目录与规范 |
| H3 | 金额字段可能用 FLOAT/DOUBLE | 财务对账精度漂移 | 统一改用 `DECIMAL(p,s)`，全局审查费用/金额字段 |
| H4 | JWT 默认密钥写死（`freight-sys-dev-secret-2026`） | 生产未配环境变量即裸奔 | 生产环境缺失密钥时应**启动即报错**，而非给默认值 |
| H5 | 跨模块事务未统一封装（订舱→财务） | 多表强一致无保障 | 抽公共事务服务层，规范事务边界 |

### 2.2 中优先级（工程化/可维护性）

| # | 缺陷 | 风险 | 改造建议 |
|---|------|------|----------|
| M1 | 无 TypeScript | 财务/报关/EDI 等正确性敏感模块缺类型约束 | 后端逐步引入 TS（或至少 JSDoc+checkjs） |
| M2 | 无单测/集成测试框架 | 高正确性模块回归风险高 | 引入 vitest/jest + supertest，覆盖财务与结算 |
| M3 | ~~JWT 仅 access token，无 refresh~~ ✅ 已完成 | ~~无法踢下线、改密失效~~ | ~~增加 refresh token + 撤销机制~~ 已实现：Sessions 表存 refresh 哈希 + 轮换；`/auth/refresh` `logout` `logout-all` `sessions` |
| M4 | 无缓存（Redis） | 高频只读查询压力大 | 热点数据加缓存层（二期） |
| M5 | 无任务队列，仅 node-cron | 场站轮询/EDI 重试等重 IO 阻塞、丢任务 | 引入轻量队列（BullMQ）做异步与重试（二期） |
| M6 | 无结构化集中日志 | 排查困难 | winston 结构化 + 集中检索（二期） |

### 2.3 低优先级（锦上添花）

| # | 缺陷 | 说明 |
|---|------|------|
| L1 | 前端无 TS、无严格 ESLint | 组件增多后维护成本上升 |
| L2 | 未做路由懒加载 / ECharts 按需引入 | 首屏体积偏大 |
| L3 | 无前端单测/E2E | 可后续补 |
| L4 | Node 版本未锁定 | 建议 .nvmrc / engines 锁定 |

### 2.4 运维/交付

| # | 缺陷 | 说明 |
|---|------|------|
| O1 | 无 CI/CD | 无自动构建、测试、部署流水线 |
| O2 | 无 Dockerfile 落地 | 影响私有化交付（文档已提，代码未落地） |
| O3 | 无监控告警 | 进程崩溃、接口 5xx、任务失败无感知 |
