# 开源升级方案（OPC / 3-4 人小团队 · 充分二开版）

> 版本：v1.0 ｜ 日期：2026-08-07
> 定位：**为 OPC（一人公司）与 3-4 人小团队设计的开源货代系统，核心竞争力 = 充分的二次开发能力**。
> 本文整合并修订现有 25 篇规划文档（见《文档总览索引》），作为下一阶段唯一执行总纲。

## 0. 定位与设计铁律

**不做的事**：不做面向大型货代的全功能广度覆盖。中小货代不会为"免费"放弃成熟商业软件（切换成本 + 本地实施服务 + 运价网络是成熟商业软件的护城河）。

**做的事**：做一个**"开箱即用的货代核心链路 + 干净好读的代码基座 + 插件化二开体系"**。目标用户是有轻度技术能力（或有一名兼职开发）的 OPC / 小团队，以及想自研但不想从零写的同业。

三条设计铁律（所有取舍以此裁决）：

1. **零运维优先** —— PostgreSQL 一键部署、一键备份（决策 3 已定稿 PostgreSQL-only，见下）。OPC 没有 DBA，系统必须"装完就跑、坏了能救"。
2. **二开优先** —— 配置 > 代码，扩展点不动核心。定制需求 80% 应通过"加一个文件/加一条配置"完成（《二开指南》已确立此哲学）。
3. **安全先行** —— 开源前必须修掉已确认的三个安全雷，否则等于公开后门。

## 2. 对既有规划的修订（重要决策点）

新定位与旧规划有 4 处冲突，建议如下（**需你拍板**）：

### 决策 1：授权策略 —— 建议 MIT 全量，放弃双授权

《开源与模块化改造方案》已定"双授权"（核心 MIT + 增值模块商业授权/LGPL）。**建议修订为 MIT 全量**：

- OPC/小团队是开源软件最敏感的受众——看到"部分模块商用需授权"会直接劝退，而这正是你要吸引的人。
- "充分二开能力"是核心卖点，许可证分层与它在传播上直接打架。
- 商业化路径改为：**托管版 / 实施服务 / 增值插件市场**（卖服务，不卖许可证）。
- 若坚持保留商业模块，可延后到 v2.0 再分层，v1 先 MIT 全量打口碑。

### 决策 2：Monorepo —— 逻辑模块化先行，物理拆分延后

原规划五阶段从 Monorepo 骨架开始，一次大重构。**建议修订**：

- 阶段 1-2 在**单仓内**完成"模块边界 + 统一注册协议（ModuleRegistry）"，目录即模块（`backend/src/modules/*`），不引入 npm workspaces。
- packages 物理拆分延后到 Phase 3（社区有真实二开需求时再做）。
- 理由：Monorepo 大重构风险高、收益后置；小团队二开者更需要"目录清晰、协议统一"，而不是构建复杂度。

### 决策 3：数据库 —— PostgreSQL-only（2026-08-09 定稿）

数据库稳定性改造已完成。**最终决策为固定 PostgreSQL-only**（用户明确选择，已落地）：

- 移除 `sqlite3` 依赖，`config`/`db` 固定 `postgres` 方言，测试默认 PostgreSQL。
- 部署经 docker-compose 的 `pg` 基础服务（或云 RDS）提供，OPC 小团队由一键编排保证零运维。
- 落实方式：`config` 按 `DB_DIALECT`（默认 postgres）切换主机参数，CI 连 PostgreSQL 测试库单跑。

### 决策 4：青岛港专项 —— 降为"官方示例插件"，不进核心

原规划将青岛港作为 P0 专项。新定位下建议：青岛港功能保留为**增值模块/示例插件**（它恰好是展示"插件协议 + 适配器 + 自动化"三合一的最佳范例），核心发行版保持港口中立。你自己用可直接启用该插件。

## 3. 升级路线图（四期）

> 工作量按 1 名熟手兼职估算；每期独立可交付、可发布。

## 5. 风险与对策

| 风险 | 对策 |
|------|------|
| 功能贪多拖垮进度 | 严格执行四期顺序；每期结束可发布一个版本 |
| Monorepo 拆分引入回归 | 逻辑模块化先行，物理拆分放 Phase 3 且有 CI 回归兜底 |
| 自定义字段性能（JSON 列查询） | 列表/搜索字段限标 `isList`；量大的团队走 PG（JSONB 索引） |
| 规则表达式注入 | 表达式白名单解析，禁止 eval；仅允许 `field op value` 组合 |
| 开源后泄敏 | Phase 0 的 .gitignore + 密钥审查进 CI（gitleaks） |
| 双数据库方言维护成本 | Sequelize 抽象 + CI 双方言跑测试；不用方言专属 SQL |
