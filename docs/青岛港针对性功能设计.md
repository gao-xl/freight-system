# 青岛港针对性功能设计

> 版本：v1.0
> 所属项目：《项目设计方案.md》阶段二（港口对接）
> 目标：针对青岛港**特有的业务时序与操作规则**，在通用货代系统之上设计一套"青岛港专项功能包"，让操作员在系统内就能掌握青岛港出口/进口的关键节点，减少人工上港查询。

---

## 1. 青岛港业务特点（为什么需要针对性功能）

通用货代系统只做"订单/订舱/跟踪"等抽象节点，无法体现青岛港以下特点：

1. **出口时序强**：青岛港出口箱有严格操作链——提箱 → 装箱 → 进港（集港/运抵）→ 运抵报告 → 报关 → 海关放行 → **装载舱单放行** → 装船。任一环节卡住都会漏装。
2. **新舱单制度**：青岛港凭**装载舱单电子数据**装船（非报关单电子放行）。报关放行后，还须确认**预配舱单是否放行、装载舱单是否已发送**，否则无法装船。
3. **码头分流**：前湾港区三大码头 **QQCT / QQCTU / QQCTN**，货代需按船公司/船靠泊码头区分操作。
4. **场站多且分散**：主流场站 30+，接口不统一（见《青岛港场站信息查询方案.md》）。
5. **费用本地化**：运抵修改费、场站费、码头费、滞箱费、搬移费、查验费等青岛本地费用项。
6. **在线平台**：青岛港云港通（qingdao-port.net）提供在线业务办理与查询。

> 针对性功能 = 把"青岛港这套特殊的货/箱/单/船节奏"内化到系统流程中，形成**可预警、可追责、可追溯**的专项能力。

---

## 2. 青岛港出口操作流程节点（系统映射基准）

| 顺序 | 业务节点 | 说明 | 系统功能支撑 |
|------|----------|------|--------------|
| 1 | 订舱 | 向船司订舱，取得 SO | 现有订舱模块 |
| 2 | 提空箱 | 到指定场站提空箱 | 节点记录 |
| 3 | 装箱/重箱回场 | 装箱后回场站 | 场站查询 |
| 4 | 进港/运抵 | 重箱集港送入码头堆场 | **进港/运抵监控** |
| 5 | 运抵报告 | 海关系统生成运抵报告 | **运抵监控** |
| 6 | 报关 | 申报并放行 | 现有报关模块 |
| 7 | 海关放行 | 报关单放行 | **放行监控** |
| 8 | 装载舱单放行 | 预配舱单放行、装载舱单发送 | **装载舱单检查** |
| 9 | 装船 | 码头理货装船 | 节点记录/船动态 |
| 10 | 离港 | 船离港 | 港口 EDI |

> 失败/异常：甩箱、未放行、运抵未生成、超期未装船 → 均需**预警**。

## 3. 青岛港进口操作流程节点（系统映射基准）

| 顺序 | 业务节点 | 说明 | 系统功能支撑 |
|------|----------|------|--------------|
| 1 | 到港/卸船 | 船舶靠泊卸箱 | 港口 EDI |
| 2 | 舱单传输 | 进口舱单传输至海关 | 报关模块 |
| 3 | 报关放行 | 申报并放行 | 报关模块 |
| 4 | 提箱/拆箱 | 码头提箱运至场站/仓库 | 场站查询 |
| 5 | 空箱归还 | 拆箱后归还空箱 | **空箱归还提醒** |
| 6 | 结算 | 滞箱费/搬移费结算 | 财务模块 |

## 4. 针对性功能清单（按优先级）

### P0 刚需（青岛港操作核心）
| 功能 | 说明 | 数据来源 |
|------|------|----------|
| **出口全程节点看板（青岛版）** | 一屏展示"提箱→装箱→进港→运抵→放行→装载舱单→装船"7 节点，红黄绿标识卡点 | 本地节点 + 场站/EDI |
| **进港/运抵监控** | 自动提醒"已进港但运抵报告未生成"、"未进港但临近截港" | 场站/EDI |
| **放行监控** | 报关放行状态监控，未放行提前预警 | 报关/EDI |
| **装载舱单检查** | 新舱单制度下，检查预配舱单放行、装载舱单发送，避免漏装 | EDI |
| **集港/截港时间管理** | 记录开港/截港时间，临近提醒 | 船期/本地配置 |

### P1 增强（青岛港效率提升）
| 功能 | 说明 |
|------|------|
| **码头分流** | 按船公司/船靠泊自动标注 QQCT/QQCTU/QQCTN，区分操作 |
| **场站/码头选择助手** | 按船公司、目的港推荐常用场站与提箱点 |
| **甩箱/改配预警** | 船期变更、舱位不足时提示甩箱风险，支持改配 | 
| **滞箱/超期预警** | 进口拆箱超期、出口在场超期 → 滞箱费预警 |
| **船舶动态** | 靠泊码头、到离港时间（对接港口 EDI） |

### P2 延展（青岛港生态）
| 功能 | 说明 |
|------|------|
| **青岛费用本地化** | 内置运抵修改费/场站费/码头费/滞箱费/搬移费/查验费等费用项模板 |
| **云港通/在线业务入口** | 跳转云港通办理在线业务，记录业务流水 |
| **青岛操作日报** | 每日汇总各订单在青岛港的关键节点完成情况 |

## 5. 数据模型扩展

### 5.1 QingdaoNode（青岛港业务节点-订购单级）
在 `ShipmentTrack` 之外，为青岛港专项节点增加结构化管理：
```js
const QingdaoNode = sequelize.define('QingdaoNode', {
  id: { type: DataTypes.INTEGER, primaryKey: true, autoIncrement: true },
  orderId: { type: DataTypes.INTEGER, allowNull: false },
  bookingId: { type: DataTypes.INTEGER },
  node: { type: DataTypes.ENUM(
    'picked_up','loaded','arrived_port','manifest_report',
    'customs_release','loading_manifest','loaded_on_board','departed'
  ) },                 // 青岛港7+节点
  status: { type: DataTypes.ENUM('pending','done','warning','blocked') },
  eventTime: { type: DataTypes.DATE },
  detail: { type: DataTypes.STRING(255) },
  source: { type: DataTypes.ENUM('manual','api','edi') },
  operator: { type: DataTypes.STRING(50) },
}, { timestamps: true, indexes: [{ fields: ['orderId', 'node'] }] });
```

### 5.2 VesselBerth（船靠泊码头记录）
```js
const VesselBerth = sequelize.define('VesselBerth', {
  id: { type: DataTypes.INTEGER, primaryKey: true, autoIncrement: true },
  vesselName: { type: DataTypes.STRING(100) },
  voyageNo: { type: DataTypes.STRING(50) },
  terminal: { type: DataTypes.ENUM('QQCT','QQCTU','QQCTN','OTHER') }, // 码头
  berthTime: { type: DataTypes.DATE },
  departTime: { type: DataTypes.DATE },
  status: { type: DataTypes.STRING(30) },
}, { timestamps: true, indexes: [{ fields: ['vesselName', 'voyageNo'] }] });
```

### 5.3 截港/开港时间
在 `Order` 或 `Booking` 增加字段：`openTime`（开港）、`cutoffTime`（截港），用于预警计算。

## 6. API 设计

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| GET | /qingdao/nodes | 某订单青岛港节点看板 | read |
| POST | /qingdao/nodes | 手动更新节点 | update |
| GET | /qingdao/checklist | 青岛港出口 checklist（7 节点） | read |
| GET | /qingdao/alerts | 青岛港预警列表（未运抵/未放行/未装/截港临近） | read |
| GET | /qingdao/berths | 船舶靠泊码头查询 | read |
| GET | /qingdao/fees | 青岛本地费用项模板 | read |

### 示例
```
GET /api/qingdao/nodes?orderId=12
GET /api/qingdao/alerts?terminal=QQCT
```

## 7. 前端页面设计

新增 **青岛港管理** 页（`/qingdao`），可分 Tab：

- **出口看板**：按订单/箱号展示 7 节点时间线 + 状态灯
- **预警中心**：未运抵 / 未放行 / 装载舱单未放行 / 截港临近 / 甩箱风险
- **船舶动态**：靠泊码头、到离港
- **码头与场站**：QQCT/QQCTU/QQCTN 分流 + 场站选择助手
- **费用模板**：青岛本地费用项维护

> 与现有 `/tracks`、`/customs`、`/finance` 联动：节点看板从各模块汇总，预警触发后可跳转对应订单。

## 8. 与现有模块的衔接

| 现有模块 | 衔接方式 |
|----------|----------|
| 订单 Order | 增加 `openTime/cutoffTime`，青岛节点挂靠 orderId |
| 订舱 Booking | 从订舱取船名/航次，关联码头分流 |
| 报关 Customs | 取放行状态 → 驱动"海关放行/装载舱单"节点 |
| 运输跟踪 tracks | 青岛节点作为青岛港专版时间线，与通用 tracks 互补 |
| 场站查询 /yards | 取"到场站/进港/运抵"状态喂给节点看板 |
| 财务 Finance | 青岛本地费用项模板，一键生成费用 |
| 港口 EDI | 取船舶动态、装载舱单、放行回执 |

---

## 9. 实施路线

1. **P0 优先**：搭建 `QingdaoNode` 模型 + `/qingdao/nodes·alerts` 接口 + 出口看板/预警中心页面。
2. **数据喂入**：接入场站查询（`/yards`）与港口 EDI，自动更新"进港/运抵/放行/装载舱单"节点。
3. **P1 增强**：码头分流、场站选择助手、船舶动态、甩箱/滞箱预警。
4. **P2 延展**：费用模板、云港通入口、操作日报。
5. **上线验证**：以真实青岛港出口/进口订单跑通"节点→预警→处理→闭环"。
