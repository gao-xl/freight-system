# 系统功能缺口与优化建议

> 版本：v1.0
> 视角：以实际使用者（货代操作员 / 业务经理 / 财务）角度对当前系统逐模块评估
> 目标：盘点"已实现但不好用"与"真实需要但欠缺"的功能，给出优先级排序与改进路线
> 依据：现有代码（`freight-system/backend`、`freight-system/frontend`）逐一核对

---

## 1. 评估结论总览

### 1.0 按团队角色功能缺口分析

> 视角：以货代团队**各业务角色**为维度，审视"每个角色在系统中缺什么才能把活干好"。与下文"按功能模块"评估互补——前者按"人"看，后者按"功能"看。

| 角色 | 核心缺口 | 关键说明 |
|------|----------|----------|
| **业务员/销售** | 报价单在线生成+一键转单、客户跟进记录(CRM)、个人业绩、客户信用额度提示 | 货代核心是抢单，销售缺工具会流失订单 |
| **操作员(进口/出口)** | 待办工作台、多箱批量管理、单据数据一键衔接、异常/卡点预警、操作日志 | 每天第一屏应是"今天该做的单" |
| **单证员** | 单证自动生成/套打、单证流转状态机、附件归档 | 提单/装箱单/发票应从订单数据派生再打印 |
| **客服/客户对接** | 客户自助查询门户、邮件/消息通知 | 船期/到港变更需自动推送 |
| **财务** | 对账/开票/核销、账龄/超期应收、单票成本归集/毛利 | 财务核心是"钱收没收到、赚没赚钱" |
| **管理层/老板** | 经营仪表盘、业务员业绩/部门对比、风险预警总览 | 决策依赖数据，缺指标则无法掌控 |
| **系统管理员** | 权限/数据范围落地、审计日志查询界面、配置化流程/字段 | 面向定制的底座能力 |

**跨角色高价值缺口（现有文档未充分覆盖）**：
1. **待办工作台/任务中心**——所有业务角色每天第一屏。
2. **客户跟进 CRM + 个人业绩**——销售最缺，货代靠抢单。
3. **单票成本/毛利核算**——财务+管理层共同刚需，决定是否赚钱。
4. **单证状态机 + 自动生成套打**——单证员核心。

### 1.1 不实用（有功能但真实用不起来）
| # | 模块 | 问题 | 建议 |
|---|------|------|------|
| 1 | 运输跟踪 | 纯手动录节点，无自动对接，且与订舱/报关状态割裂 | 按订单自动生成节点时间线，对接外部数据自动打点 |
| 2 | 经营看板 | 只有总数卡片+饼图，缺经营指标 | 增加在途/账龄/回款率/业绩等实用视图 |
| 3 | 订单状态流转 | 四态手动推进，与业务节点脱节 | 用业务节点状态机替代，与跟踪/报关联动 |
| 4 | 财务管理 | 仅应收应付流水，无对账/开票/账龄/超期提醒 | 补对账/开票/账龄/超期提醒 |

### 1.2 欠缺（真实需要但没有）
| 优先级 | 欠缺功能 | 说明 |
|--------|----------|------|
| 高 | 单证/文件附件上传 | 只能填单证号/标题，不能上传提单/发票/装箱单 |
| 高 | 打印/导出 | 订单/提单/对账单/报表均不能导出 PDF/Excel |
| 高 | 预警/提醒 | ETA临近、船期、报关临期、超期应收、截港——全无 |
| 中 | 经营指标 + 账龄 | 回款率、利润率、超期应收账龄、业务员业绩 |
| 中 | 客户自助查询门户 | 客户不能自排查件状态 |
| 中 | 多箱/箱号管理 | 订单仅一个 containerNo，一单多箱无法维护 |
| 中 | 组合筛选 | 缺按客户/业务员/日期范围/航线的组合筛选 |
| 中 | 操作日志/审计 | 谁改了什么不可追溯 |
| 低 | 多币种汇率换算 | 财务仅金额+币种字段，无汇率换算 |
| 低 | 信用额度管控 | 客户超限预警/拦截 |

## 2. 不实用功能详解

### 2.1 运输跟踪（最不实用）
- **现状**：`TrackingList.vue` 是一张手动录入的表，操作员逐条填"阶段/地点/描述"，无任何自动对接（AIS/船司/港口）。
- **问题**：
  - 高频维护成本高，操作员无法坚持使用。
  - 阶段（已订舱/已提货/已装船/已到港/已清关/已送达）与订舱、报关模块状态重复，信息割裂。
- **改进方向**：
  - 以订单为主线自动生成节点时间线。
  - 接入外部数据（AIS、港口 EDI、场站）自动打点，手动仅做补充。
  - 与订舱/报关/财务状态联动，形成统一在途视图。

### 2.2 经营看板（信息价值低）
- **现状**：`Dashboard.vue` 为总数卡片 + 订单状态/运输模式两张饼图 + 最近订单表。
- **问题**：
  - 无"在途订单、ETA临近、超期应收、回款率、业务员业绩"等经营指标。
  - 饼图对决策帮助有限。
- **改进方向**：
  - 增加经营指标卡片：在途订单、本月回款率、超期应收、待装船。
  - 增加实用视图：应收账龄、业务员业绩排行、利润趋势。

### 2.3 订单状态流转（过于简陋）
- **现状**：`OrderDetail.vue` 仅 `draft→confirmed→in_progress→completed` 四态手动推进。
- **问题**：与真实业务节点（订舱→进港→报关→装船→到港→清关→送达）脱节。
- **改进方向**：用业务节点状态机替代，节点由订舱/报关/跟踪驱动，前端展示流转图。

### 2.4 财务管理（过于流水化）
- **现状**：`FinanceList.vue` 仅应收应付流水 + 手动"记为已收付" + 月度趋势图。
- **问题**：无对账单、开票、核销、账龄、超期提醒，财务用户实际用不起来。
- **改进方向**：
  - 对账单生成与客户在线确认。
  - 开票记录、收款/付款核销。
  - 应收账龄分级 + 超期自动提醒。

## 3. 欠缺功能详解

### 3.1 高优先级
| 功能 | 详情 |
|------|------|
| **单证附件上传** | `Document` 增加文件字段（本地/OSS 存储），前端支持上传/下载/预览。货代核心是文档流转，此缺口最大。 |
| **打印/导出** | 订单、提单、对账单、报表导出 PDF/Excel。对接打印模板。 |
| **预警/提醒** | 规则引擎：ETA临近、船期变更、报关临期、超期应收、截港时间。可对接青岛港节点（见《青岛港P0功能技术实现步骤.md》）。 |

### 3.2 中优先级
| 功能 | 详情 |
|------|------|
| **经营指标 + 账龄** | 看板增强：回款率、利润率、超期应收账龄、业务员业绩。 |
| **客户自助查询门户** | 面向客户企业级的自助跟踪门户（二期规划）。 |
| **多箱/箱号管理** | 订单关联集装箱表 `OrderContainer`，支持一单多箱、多箱状态。 |
| **组合筛选** | 列表页增加客户/业务员/日期范围/航线组合筛选。 |
| **操作日志/审计** | 关键操作记录操作人、时间、变更前后。 |

### 3.3 低优先级
| 功能 | 详情 |
|------|------|
| **多币种汇率换算** | 财务增加汇率换算与币种结算。 |
| **信用额度管控** | 客户信用额度、超限预警/拦截订舱。 |

## 4. 优先级排序（P0/P1/P2）

| 优先级 | 功能 | 理由 |
|--------|------|------|
| **P0** | 单证附件上传 | 货代日常硬需求，缺失则无法真正干活 |
| **P0** | 打印/导出 | 对外发文件必备 |
| **P0** | 预警/提醒（ETA/超期应收/截港） | 减少漏单、漏款、漏装 |
| **P1** | 经营指标 + 账龄 | 管理层决策必需 |
| **P1** | 运输跟踪改造（自动节点时间线） | 提升在途可视性，可接青岛港P0方案 |
| **P1** | 订单状态机（业务节点化） | 流转可视化，与跟踪/报关联动 |
| **P1** | 财务对账/开票/核销 | 财务模块真正可用 |
| **P2** | 客户自助查询门户 | 提升客户服务体验 |
| **P2** | 多箱/箱号管理、组合筛选、操作日志 | 数据完整性与可追溯 |
| **P2** | 多币种、信用额度 | 规模化后增强 |

---

## 5. 改进路线（分批实施）

### 批次 A：P0 硬需求（先让系统"能干活"）
1. **单证附件上传**：`Document` 增加文件字段 + 上传/下载/预览接口与页面。
2. **打印/导出**：订单、提单、对账单导出 PDF/Excel。
3. **预警/提醒**：规则引擎 + 定时任务，覆盖 ETA临近/船期/报关临期/超期应收/截港。

### 批次 B：P1 管理增强（让系统"有决策价值"）
1. **经营指标 + 账龄**：看板增强。
2. **运输跟踪改造**：自动节点时间线，联动订舱/报关/财务。
3. **订单状态机**：业务节点化流转图。
4. **财务对账/开票/核销**：财务模块完善。

### 批次 C：P2 服务与规模化
1. **客户自助查询门户**。
2. **多箱/箱号管理、组合筛选、操作日志**。
3. **多币种、信用额度管控**。

> 与《项目设计方案.md》阶段一/二/三对齐：批次 A/B 对应阶段二增强，批次 C 对应阶段三规模化。青岛港针对性功能（《青岛港P0功能技术实现步骤.md》）可与批次 B 的运输跟踪改造合并实施。

---

## 6. 落地建议

1. **先 P0**：补齐附件上传 + 打印导出 + 预警，这是让系统可用的最小增量。
2. **跟踪+预警一体化**：把"运输跟踪改造"与"青岛港节点看板"合并，避免重复建设。
3. **复用现有模式**：预警走《控制性设计手册》定时任务；附件存储按《项目设计方案.md》走 OSS/本地。
4. **分模块验收**：每个批次独立回归，避免大版本高风险。
