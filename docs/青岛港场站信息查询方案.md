# 青岛港场站信息查询功能方案

> 版本：v1.0
> 所属项目：《项目设计方案.md》阶段二（港口对接）
> 目标：针对青岛港**主流集装箱场站**（堆场），提供集装箱/提单信息查询能力，打通"箱在哪个场站、是否进场、是否放行、是否查验"等关键在途节点，提升货代对货物状态的掌控。

---

## 1. 背景与价值

### 1.1 为什么需要场站查询
青岛港的集装箱在**码头（QQCT/QQCTU）与场站（堆场）**之间流转。对货代而言，最关心的不只是"船到没到"，还有：
- **出口重箱**是否已进指定场站、是否收箱
- 是否已放行（海关放行/场站放行）
- 是否已集港（送入码头堆场）
- 是否查验、查验结果
- 进口拆箱、提箱状态

这些信息散落在各场站自有系统中，货代操作员目前靠**人工访问各场站网页、电话、微信**查询，效率低且易错。

### 1.2 与港口 EDI 平台的区别
| 对比 | 港口 EDI 平台（见《港口官方平台对接方案.md》） | 场站信息查询（本文档） |
|------|------------------------------------------|---------------------|
| 主体 | 山东港口青岛港 EDI 中心 | 独立场站/船公司堆场 |
| 数据 | 船舶动态、码头装卸 | 箱在堆场状态、放行/查验 |
| 入口 | 统一 EDI/API | 各场站独立系统，接口不统一 |
| 开通 | 需向港方申请 | 需逐一与场站/港方协商 |

> 场站查询 = 港口宏观动态的**最后一公里**，两者互补，共同构成完整在途视图。

### 2.2 现实约束（关键）
1. **接口不统一**：绝大多数场站仅有网页表单查询（.aspx/.jsp），**无开放 REST API**，无统一报文规范。
2. **需商务开通**：批量/自动查询需与场站或港方签署数据服务协议，获取账号与授权。
3. **数据时效**：部分场站查询需登录，数据更新有延迟（T+0~T+1）。
4. **合规**：抓取场站网页需获得授权，避免违反服务条款。

> 因此，本方案采用**"统一架构 + 多落地模式"**，先做可控的场站，逐步扩展。

## 3. 落地模式（三种可选）

| 模式 | 说明 | 适用 | 成本 | 时效 |
|------|------|------|------|------|
| **A. 官方对接** | 与场站/港方签署协议，通过其 EDI/API/文件交换获取数据 | 主流大场站（长荣/捷丰/大亚/QQCT） | 中-高 | 实时/T+0 |
| **B. 页面抓取（授权）** | 在获得授权后，程序模拟查询场站网页 | 有网页查询但无 API 的场站 | 低-中 | T+0~T+1 |
| **C. 人工维护** | 操作员在系统内手动录入/复制场站查询结果 | 无任何接口、量小的场站 | 低 | 人工 |

> 建议**A 为主、B 为辅、C 兜底**。系统对三种模式统一建模，前端无感知。

## 4. 统一架构设计

### 4.1 复用现有适配器模式
沿用 `src/integrations/adapters/` + `IntegrationClient` 工厂，统一 `query()` 接口。

```
src/integrations/adapters/
├── yardQingdao.js     # 青岛港场站（含多个场站子路由）
└── ...                # 后续可按场站拆分 yardEvergreen / yardSmart 等
```

### 4.2 服务层（`src/services/yardService.js`）
对外统一入口，屏蔽场站差异：
```js
// 场站排序与查询

```

### 4.3 适配器示例（`src/integrations/adapters/yardQingdao.js`）
```js
// 青岛港场站状态查询适配器
// 真实环境：按场站 mode 分发到 官方API / 授权抓取 / 人工录入。
const axios = require('axios');
const crypto = require('crypto');
const code = 'yard_qingdao';

function pathFor(yardCode) {
  // 官方对接场站：统一走港方网关
  return `${API_BASE}/yard/${yardCode}/status`;
}

async function query(cfg, { containerNo, billNo, yardCode }) {
  const url = pathFor(yardCode);
  const headers = {
    'Content-Type': 'application/json',
    'X-Enterprise': cfg.enterpriseCode,
    'X-Sign': sign(cfg, { containerNo, billNo }),
    'X-Timestamp': Date.now(),
  };
  const params = { containerNo, billNo };
  const resp = await axios.post(url, params, { headers, timeout: 15000 });
  return normalize(resp.data);   // 统一字段映射
}

function sign(cfg, payload) {
  const raw = JSON.stringify(payload) + (cfg.secret || '');
  return crypto.createHmac('sha256', cfg.secret || '').update(raw).digest('hex');
}

// 将各场站异构返回统一为系统标准字段
function normalize(raw) {
  return {
    yardCode: raw.yardCode,
    containerNo: raw.containerNo,
    billNo: raw.billNo,
    status: mapStatus(raw.status),   // 在场/放行/集港/查验/提取
    location: raw.location,
    eventTime: new Date(raw.eventTime),
  };
}

module.exports = { code, name: '青岛港场站', query };
```

## 5. 数据模型

### 5.1 YardRecord（场站状态记录）
```js
const YardRecord = sequelize.define('YardRecord', {
  id: { type: DataTypes.INTEGER, primaryKey: true, autoIncrement: true },
  orderId: { type: DataTypes.INTEGER },          // 关联订单（可选）
  containerNo: { type: DataTypes.STRING(30) },    // 箱号
  billNo: { type: DataTypes.STRING(50) },         // 提单号
  yardCode: { type: DataTypes.STRING(30) },       // 场站编码
  yardName: { type: DataTypes.STRING(50) },       // 场站名称（冗余）
  status: { type: DataTypes.STRING(30) },         // 在场/放行/集港/查验/提取
  location: { type: DataTypes.STRING(100) },      // 场地区位
  eventTime: { type: DataTypes.DATE },
  source: { type: DataTypes.ENUM('api', 'scraper', 'manual') }, // 数据来源
  raw: { type: DataTypes.TEXT },                  // 原始回执
  queryBy: { type: DataTypes.INTEGER },           // 查询人
  queryAt: { type: DataTypes.DATE },              // 查询时间
}, { timestamps: true, indexes: [
  { fields: ['containerNo', 'yardCode'] },
  { fields: ['billNo'] },
] });
```

### 5.2 YardMeta（场站名录，静态维护）
```js
const YardMeta = sequelize.define('YardMeta', {
  code: { type: DataTypes.STRING(30), unique: true },  // 场站编码
  name: { type: DataTypes.STRING(50) },                // 场站名称
  mode: { type: DataTypes.ENUM('api', 'scraper', 'manual') },
  enabled: { type: DataTypes.BOOLEAN, defaultValue: true },
  remark: { type: DataTypes.TEXT },
}, { timestamps: true });
```

### 5.3 配置（IntegrationConfig seed）
```js
{ code: 'yard_qingdao', name: '青岛港场站', enabled: false,
  config: '{"enterpriseCode":"", "secret":""}', remark: '长荣/捷丰/大亚/QQCT 等场站状态' }
```

## 6. API 设计

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| GET | /yards | 场站名录列表 | read |
| GET | /yards/status | 按箱号/提单号+场站查询 | read |
| POST | /yards/query | 手动触发场站状态查询 | update |
| GET | /yards/records | 历史查询记录（按订单/箱号） | read |
| PUT | /yards/:id | 人工录入/修正场站状态 | update |

### 示例
```
GET /api/yards/status?containerNo=COSU1234567&yardCode=evergreen
GET /api/yards/records?orderId=12
```

### 响应示例
```json
{
  "code": 0,
  "data": {
    "containerNo": "COSU1234567",
    "yardCode": "evergreen",
    "yardName": "长荣场站",
    "status": "放行",
    "location": "A区12排",
    "eventTime": "2026-08-07T10:00:00+08:00",
    "source": "api"
  }
}
```

## 7. 前端页面设计

新增 **场站查询** 页面（`/yards`），归属"运输跟踪"模块：

- **查询区**：箱号 / 提单号 / 场站（多选）→ 查询
- **结果区**：表格展示各场站返回的箱状态、区位、时间、来源
- **历史记录**：按订单/箱号查看历史查询轨迹
- **关联订单**：可从 `ShipmentTrack` 节点跳转，展示"场站状态"时间线
- **人工录入**：对 no API 场站，提供手动新增/编辑入口（source=manual）

```
/transport
  └── /yards      场站信息查询
      └── 场站详情（状态时间线）
```

## 8. 数据同步与缓存

| 数据 | 方式 | 频率 |
|------|------|------|
| 在途订单箱状态 | 定时轮询 + 订单触发 | 在途每 30 分钟 |
| 场站名录 | 后台维护 | 手动 |
| 已完结订单 | 不再轮询 | — |

> 接入《控制性设计手册》定时任务，缓存结果（如 30 分钟），避免频繁调用场站系统、降低被限流风险。

## 9. 安全与合规

| 项 | 要求 |
|----|------|
| 授权 | 与场站/港方签署数据服务协议，取得账号与授权 |
| 密钥 | 企业备案号、密钥加密存储，不进代码库 |
| 签名 | 请求签名 + 时间戳防重放 |
| 抓取合规 | 仅获授权场站才启用抓取，控制频率，遵守 robots/服务条款 |
| 数据合规 | 场站数据仅限内部业务使用，不对外泄露 |
| 日志 | 记录查询报文与回执（可追溯、可审计） |

## 10. 实施路线

1. **盘点签约**：与主流场站（长荣/捷丰/大亚/QQCT）商务洽谈，获取查询授权与接口/网页规范。
2. **建表与配置**：新增 `YardRecord`、`YardMeta` 模型，`seed.js` 增加 `yard_qingdao` 配置。
3. **适配器与服务**：实现 `yardQingdao.js` 适配器 + `yardService.js` 统一查询。
4. **接口与前端**：新增 `/yards/*` 接口与场站查询页面，接入运输跟踪时间线。
5. **定时同步**：接入定时任务轮询在途订单箱状态。
6. **上线验证**：以真实箱号跑通"查询→落库→展示→时间线"闭环。

---

## 11. 验收标准

- [ ] 场站名录可维护（增删改）
- [ ] 至少 1 个主流场站（如长荣）跑通自动查询
- [ ] 按箱号/提单号+场站返回统一结构状态
- [ ] 查询结果落库并可回溯历史
- [ ] 关联订单，运输跟踪时间线展示场站节点
- [ ] 人工录入模式可用（source=manual）
- [ ] 定时任务稳定，无频繁调用、无越权查询
